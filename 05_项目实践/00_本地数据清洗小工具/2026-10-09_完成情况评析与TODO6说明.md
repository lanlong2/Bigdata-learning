## TODO 6到底做什么

`用任务书里的边界情况检验程序`表示：换成很小、很特殊的输入，运行整个程序，比较实际结果和预期。样例包含多笔正常订单，只有表头、单条订单、0单价等输入能检查循环没有执行、只执行一次或数值恰好到临界点时的行为。

它是一项检验工作。可以先手动换测试文件、运行、记录结果；不要求一定在注释下面新增一段业务逻辑，也不要求马上使用测试框架。

### 必做的两个小输入

**只有表头：**

```csv
order_id,product,quantity,unit_price
```

预期：有效、重复、无效、总数量、销售额全部为0；各商品销量为空字典；干净CSV只有表头；JSON仍需生成。

**只有一条有效订单：**

```csv
order_id,product,quantity,unit_price
O100, Pen ,2,3
```

预期：有效1、重复0、无效0、总数量2、销售额6，商品销量`{"pen": 2}`；CSV保留这笔订单，商品名成为`pen`。

### 再检查规则的边界

| 输入情况 | 应得到的结果 |
|---|---|
| 数量1、单价0 | 有效订单；销售额0 |
| 数量0或负数、单价负数、数字字段为`abc` | 无效行，记录原因，后续行继续处理 |
| 同编号两条有效订单 | 保留第一条；重复行加1；第二条不参与数量和销售额累计 |
| 同商品不同编号 | 都保留；该商品销量为各笔数量之和 |
| 编号或商品为空／只有空格 | 无效行 |
| 完全空白行与`,,,` | 前者由读取器忽略，后者计无效行 |
| 同编号先无效后有效 | 前者计无效，后者保留，不计重复 |
| 同一输入连续运行两次 | CSV和JSON内容一致，第二次不累加第一次的结果 |

### 手动操作方法

1. 在`data`里另建`只有表头.csv`和`单条订单.csv`，分别放入上面的内容，保留原始示例。
2. 每次把`input_file`临时指向一个测试文件，保存后运行整个`main.py`。
3. 对照预期检查终端、干净CSV与统计JSON；当前JSON输出补齐后再检查JSON。
4. 记录输入、预期、实际结果及需要调整的地方。测试会覆盖当前输出，这是任务书要求的重复运行行为。
5. 检查结束把`input_file`改回`示例订单.csv`，重新生成样例结果；在README中用自己的话补写流程和测试情况。
