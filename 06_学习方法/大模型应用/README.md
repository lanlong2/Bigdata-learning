# 大模型应用怎样学

本路线目标是Python大模型应用实习基础，预算175小时，先于Java学习。Python基础已完成，不重学整套入门；SQL、Python工程、HTTP和API按依赖接续。

| 模块 | 小时 | 学习时最需要解释的问题 |
|---|---:|---|
| A00 SQL共用基础 | 35 | 每行代表什么，如何筛选、关联、统计和处理空值？ |
| A01 Python工程 | 20 | 项目怎样分模块、管理依赖、处理配置、记录日志和测试？ |
| A02 HTTP与FastAPI | 25 | 一个请求怎样校验、处理并返回成功或错误？ |
| A03 模型API | 15 | 怎样控制输入输出、处理超时、记录调用量和保护密钥？ |
| A04 RAG与评测 | 35 | 如何找到依据，引用是否支持回答，何时应拒答，修改是否有效？ |
| A05 独立项目 | 45 | 能否把上述能力组成可复现、可解释的[资料问答服务](../../05_项目实践/大模型应用/00_资料问答服务/README.md)？ |
| 合计 | 175 | 练习、排错和项目已包含 |

第一次见到术语先在教材中弄清含义，再运行最小示例。HTTP是客户端与服务器交换请求和响应的约定；API是程序之间约定的调用入口；这些并不因已会Python自动掌握。RAG的学习放在能调用模型接口之后，不先背框架名词。

每天使用[90分钟共用方法](../共用工程/README.md)。看一次示范后自己修改输入，预测结果再运行；从“接口能返回结果”继续做到“来源和结果能解释”。答案看起来流畅时也要回查原资料，不能用语言自然代替事实正确。

评测时固定问题、资料版本和判定规则，分开观察可回答问题、资料外问题与冲突问题。失败先判断出在资料、检索、上下文、提示还是模型输出，再改一个因素。原理讲解可看[来源不足时怎么办](../../08_案例学习/大模型应用/01_来源不足时怎么办.md)，案例不是独立项目完成。

不把训练大模型、深入微调、本地部署大模型或复杂多Agent加入本路线必修。硬件和API方案在需要时选择，核心是能解释和维护应用链路。175小时是控范围的计划，不能靠压缩Java时间无限扩展。

基础阶段不用AI代写；项目阶段可部分使用AI并理解、修改、核对对应代码。完成情况按用户事实记录，材料创建不计作学习完成。
