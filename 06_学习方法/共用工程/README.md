# 90分钟学习与工程实践

2026-10-23确定：每天90分钟，每周学习6天，共9小时；第7天不安排学习任务。学习预算700小时，先完整推进大模型应用175小时，再完整推进Java后端450小时，另有75小时技术巩固与返修。周安排是计划，实际完成与用时按用户陈述记录。

## 每次90分钟怎样用

| 用时 | 活动 | 具体产出 |
|---|---|---|
| 10分钟 | 接续与回忆 | 找到上次停点，口述一个原理或重写一小段已学逻辑 |
| 20分钟 | 学一个小主题 | 阅读教材，预测示例行为，弄清新术语与输入输出 |
| 40分钟 | 独立实现或练习 | 完成一个可核对的小目标，包含必要的调试 |
| 15分钟 | 核对与解释 | 对照规则、补边界、说明原因；技术追问练习也在这里 |
| 5分钟 | 保存与接续 | 保存变更，写明下一次第一步和未解决点 |

项目日可以把20分钟阅读并入实现与调试；整次仍控制在90分钟。一次目标应具体到“完成一个接口的输入校验并核对三种输入”，不要写成“学习Spring”或“完善项目”。任务尚未完成时保留可接续状态，不为了当日打钩直接复制答案。

## 每周六次怎样衔接

| 单元 | 建议用途 |
|---|---|
| 第1—3次 | 按知识依赖推进新内容与配套练习，每次都核对基本行为 |
| 第4次 | 将本周知识合成一个小流程，或推进当前主项目 |
| 第5次 | 集中处理卡点、边界、回归检查和技术解释 |
| 第6次 | 收尾与复盘：整理实际完成、订正、用时和下周第一步；其余时间继续技术练习 |

每周复盘在第6次内安排15—20分钟，不另加90分钟。项目阶段六次都可以围绕同一主项目推进，不要求每周新增技术。算法、网络、数据库和代码解释都是技术学习，不能推迟到预算之外的“面试准备”才开始。

## 先完成一条路线，再学习下一条

大模型阶段只学到支撑受控Python应用所需的知识。达到路线的完成目标后收尾，不继续深入训练、微调或堆叠Agent功能；随后集中学习Java。

Java阶段可以修复已完成Python项目的错误、重启服务或回顾关键知识；这些属于维护和巩固，不是并行开新一轮大模型课程。发生维护用时就计入技术预算，避免隐形增加学习负担。

75小时返修用于真实薄弱点、项目故障、重新部署和必要改进；可在阶段交界或后期分配，不是停止学习的缓冲假期。技术返修也不能变成无限增加扩展功能。简历、投递、模拟和正式面试另计；项目中的技术文档、演示运行与设计解释计入学习。

## AI协作边界

基础学习与日常独立练习不使用AI代写代码。可以让AI解释术语、提问、指出错误位置、给逐级提示或批改；先得到提示再自己实现，不把自动补全或整段生成当作独立练习。

复杂项目启动后可以部分使用AI。采用之前至少做到：

1. 自己说清需求、输入输出和业务限制。
2. 逐段读懂会执行什么，指出异常路径和外部依赖。
3. 能修改一个需求，写测试或运行核对，并说明结果。
4. 不理解的部分先拆小、查资料或改成能够维护的方案。

上述是能力训练建议。用户说明“已完成”“已掌握”等时直接记录，不将提交代码、演示或助手验证设为写入完成状态的前置。AI辅助与独立完成按用户实际说明分别记录，不补造活动或用时。

## 卡点与第二天恢复

先比较预期与实际，读完整报错，再缩小到最小可复现问题。请求失败就沿“输入→接口→业务规则→数据库或外部服务→输出”逐层定位，一次只验证一个主要猜想。

独立尝试一段时间仍没有新线索时，带着代码、预期、报错和尝试求助，要求先提示。不要只消耗固定时长反复猜测；也不要求在基础阶段为解决一个问题临时学完整套高级框架。

结束前留下四项即可：已经运行到哪一步、最后的完整错误或现象、当前最可能原因、下一次先做什么。临时中断就从这四项恢复；实际少学的时间如实记，不编造完成，也不自动把全部积欠堆到下一天。

## 保存成果与学习事实

代码、SQL、测试和技术说明保存在对应练习或项目目录。使用[Git说明](../../01_学习笔记/Git/README.md)保存有意义的改动；不提交密钥、密码和本地临时环境。

学习、练习、订正、复测与项目活动分别记录。用户明确说明已完成、已订正、已学完、已达标、已掌握、复测通过或实际用时，直接记为事实；后续复习或检查不反向取消已经确认的事实。旧分数与历史原件保留。

错题与疑问是否收入04由用户选定；卡点先记录在当前练习或项目旁，不自动写入04。教材和任务书由助手创建只说明材料已建立，不说明用户已经学习。
