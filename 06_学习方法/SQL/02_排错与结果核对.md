# SQL排错与结果核对

先区分“语句不能执行”和“可以执行但结果不对”。错误信息通常指向语法或对象位置；成功执行只代表数据库接受了语句，还要核对业务问题。

| 现象 | 先检查什么 |
|---|---|
| 连接失败 | PostgreSQL服务、所选服务器、端口、数据库名和登录账号；不要把密码写进学习文件 |
| 表不存在 | 是否执行初始化脚本，是否连接同一练习库，是否设置sql_learning搜索路径 |
| 列不存在 | 字段名是否与表一致，是否误用别名或另一张表的字段 |
| 没有结果 | 筛选值是否匹配，大小写是否一致，NULL是否用IS NULL判断 |
| 行数比预期多 | 连接条件是否缺失，一个客户是否本来对应多笔订单 |
| 统计数字偏大 | 是否把取消订单计入，连接后是否重复计数，统计的是订单数还是数量 |
| 顺序每次不同 | 是否显式ORDER BY，同值时是否补稳定排序字段 |

上表中JOIN、别名作用范围等内容，学到对应教材后再使用。基础阶段先练从原表逐步加WHERE、选列和排序，观察哪一步改变结果。

每条查询都核对：每行代表什么、是否漏掉0记录或NULL、COUNT数的是行还是非空字段、金额是否为数量乘单价。课程样例的paid订单为7笔、数量14、金额40；这些数字用于核对，不能直接写成查询答案。

报错时提供自己正在学的模块、完整SQL、完整错误信息、预期结果和已尝试的修改，隐藏登录密码等无关信息。
