# 路线导读与Python工程补齐

对应A01，完整阶段预算20小时；本篇是可直接学习的起始教材。**先完成A00的SQL教材和习题，再正式进入本篇。** Python00—09与M01—M06已完成，只回查卡点，不重新计为未学。工程补齐后续的类、测试框架和依赖管理深入内容按实际需要展开，不把本篇当作已覆盖整个工程开发。

## 1. 从“写一段代码”到“维护一个程序”

工程在这里指：让代码在明确的环境中运行，输入输出位置稳定，出错时知道哪里出了问题，修改后能检查旧功能是否仍正常。你已学过函数、模块、类型注解、异常和文件读写，现在把它们组织成一个可重复运行的小程序。

本篇最终做一个“资料标题整理程序”：读取JSON中的标题，去掉前后空白、丢弃空标题、保留首次出现顺序并去重，写出报告。它是后续资料问答导入流程的一个小步骤，不是另一个必交的大项目。

本篇所有代码均为教材示例。先理解和手写，再用配套题独立练习；示例运行不代表你已独立完成习题或项目。

## 2. 解释器、虚拟环境和依赖

**解释器**是实际执行Python代码的程序。同一台电脑可能有多个Python，编辑器里选择的解释器和终端运行的解释器也可能不同。

先在PowerShell逐行执行：

```powershell
python --version
python -c "import sys; print(sys.executable)"
```

`--version`显示版本；`-c`表示直接执行后面的短Python语句。`sys.executable`显示本次执行使用的解释器路径。路径因电脑不同而不同，不要求与你的同学相同。如果`python`命令不可用，先复用现有编辑器中已经能运行Python的环境；Windows已安装启动器时也可尝试`py -3 --version`，不要直接重装一套重复环境。

**依赖**是程序需要的其他库。`json`、`pathlib`、`logging`属于Python自带的标准库；FastAPI等属于额外安装的第三方库。

**虚拟环境**是一个项目单独使用的Python与依赖目录，避免项目之间安装不同版本时互相影响。它不复制整个操作系统，也不保存源码。将自己的练习放在一个新的小目录，例如`title_cleaner`，进入该目录后执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip --version
```

`-m venv`是用当前解释器运行名为`venv`的标准库模块；`.venv`是本项目环境目录。后两行显式调用它，避免PowerShell激活策略影响入门，不要求修改系统执行策略。

以后运行本项目时使用这个解释器。安装第三方依赖也使用同一个解释器的`-m pip`，不要把一个环境里的`pip`与另一个环境里的`python`混用。本篇不需要安装第三方库。

当项目真正安装了FastAPI等第三方依赖时，可在这个独立环境执行：

```powershell
.\.venv\Scripts\python.exe -m pip freeze > requirements.txt
```

`requirements.txt`记录当前环境的第三方依赖版本；在新建的兼容环境可以用`python -m pip install -r requirements.txt`安装。它不是跨平台和跨Python版本的绝对复现保证；第一遍先理解用途，后续再学更严格的依赖锁定。

完成小检查：分别解释源码目录、`.venv`和`requirements.txt`保存什么。虚拟环境和缓存通常不加入Git，依赖清单应加入；在项目实际配置前检查已有`.gitignore`。

## 3. 让路径跟着代码的位置走

**当前工作目录**是终端当前所在目录，`Path("data/input.json")`默认相对它解释。换一个终端目录，可能就找不到同一个文件。

**脚本目录**是当前`.py`文件所在的位置。对这个小程序，约定数据总在脚本旁边的`data`目录，输出总在`output`目录：

```python
from pathlib import Path

base_dir = Path(__file__).resolve().parent
input_path = base_dir / "data" / "input.json"
output_path = base_dir / "output" / "report.json"

print(input_path.name)
print(output_path.parent.name)
```

保存为`.py`后运行，输出：

```text
input.json
output
```

`__file__`是本脚本路径，`resolve()`得到绝对路径，`parent`取父目录，`/`在Path对象之间用于拼接路径，`name`取最后的名字。它们不要求路径已经存在；读取时不存在才会报错。交互输入窗口可能没有`__file__`，所以本例必须保存为脚本。

写文件前用`output_path.parent.mkdir(parents=True, exist_ok=True)`创建父目录：`parents=True`允许补齐缺失的上层目录，`exist_ok=True`表示已存在时继续。这不清空旧目录。`write_text`写同名文件会覆盖原内容，因此练习使用新目录，不指向历史答卷。

## 4. 完整程序：输入、处理、输出分开

先手动建立下面的目录和文件。`.venv`由前面的命令创建，`output`由程序创建：

```text
title_cleaner/
  .venv/
  app.py
  check.py
  data/
    input.json
  output/                 # 运行后生成
    report.json
```

`data/input.json`内容为：

```json
[" SQL入门 ", "Python基础", "SQL入门", "", "   "]
```

将下面完整内容手写到`app.py`。本例输入必须是字符串列表，空字符串可以清洗掉；数字、对象等类型不符合约定，程序拒绝这类输入，而不是悄悄转换。

```python
import json
import logging
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent


def clean_titles(raw: list[str]) -> list[str]:
    if not isinstance(raw, list):
        raise ValueError("输入必须是列表")

    result: list[str] = []
    for value in raw:
        if not isinstance(value, str):
            raise ValueError("每个标题必须是字符串")
        title = value.strip()
        if title and title not in result:
            result.append(title)
    return result


def build_report(raw: list[str]) -> dict:
    titles = clean_titles(raw)
    return {
        "input_count": len(raw),
        "valid_count": len(titles),
        "titles": titles,
    }


def main() -> int:
    logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s")
    input_path = BASE_DIR / "data" / "input.json"
    output_path = BASE_DIR / "output" / "report.json"

    try:
        raw = json.loads(input_path.read_text(encoding="utf-8"))
        report = build_report(raw)
        output_path.parent.mkdir(parents=True, exist_ok=True)
        output_path.write_text(
            json.dumps(report, ensure_ascii=False, indent=2),
            encoding="utf-8",
        )
    except (OSError, ValueError) as exc:
        logging.error("处理失败：%s", exc)
        return 1

    logging.info("已写入 %s，保留 %s 个标题", output_path.name, report["valid_count"])
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

在`title_cleaner`目录运行：

```powershell
.\.venv\Scripts\python.exe app.py
$LASTEXITCODE
```

成功时日志与退出码为：

```text
INFO 已写入 report.json，保留 2 个标题
0
```

`output/report.json`是：

```json
{
  "input_count": 5,
  "valid_count": 2,
  "titles": [
    "SQL入门",
    "Python基础"
  ]
}
```

### 分步解释

1. `clean_titles`只负责规则，不读文件也不打印。`isinstance(value, str)`检查运行时实际类型；类型注解只表达约定，不会自动阻止传入数字。
2. `strip()`去掉首尾空白；`if title`排除空字符串；列表查重保留首次出现顺序。这里数据很小，先选容易理解的写法，大量数据时再讨论集合辅助查重。
3. `build_report`组合规则与计数。`valid_count`是最终保留的标题数，不是输入中所有非空标题的数量；重复项也不保留。
4. `main`负责文件路径、读写、日志与退出码。`json.loads`解析文本，`json.dumps`生成文本；`ensure_ascii=False`保留可读中文，`indent=2`让JSON缩进。
5. 无效JSON会产生`ValueError`的子类异常；文件不存在、权限等通常产生`OSError`或它的子类。程序处理这两类预期失败，其他程序缺陷仍会暴露报错，便于定位。
6. `logging.info`记录正常运行信息，`logging.error`记录失败。`%s`与后面的参数对应，日志系统负责格式化；格式中的`%(levelname)s`和`%(message)s`表示等级和内容。
7. `main`返回整数；`SystemExit`让程序退出并把这个整数交给系统。0表示成功，1表示本程序的失败；`$LASTEXITCODE`是PowerShell查看上一个外部程序退出码的方式。
8. 导入`app`时，`if __name__ == "__main__"`下面不会执行，因此测试可以只导入函数，不触发文件写入。

边界：如果本次处理失败，之前存在的`report.json`不会自动删除，不能把旧报告当作新一次成功结果；以本次退出码和日志判断。本示例未做并发写入、原子替换或大文件流式处理，这些属于后续项目需要时再学的内容。

## 5. 检查修改有没有破坏旧规则

**测试**是给程序已知输入，比较实际结果与预期。不是只看“没有报错”，而是检查内容是否正确。先用Python自带的`assert`写最小检查；断言为假会抛出`AssertionError`。

`check.py`完整内容：

```python
from app import build_report, clean_titles

assert clean_titles([" A ", "A", "", " B "]) == ["A", "B"]
assert clean_titles([]) == []
assert build_report(["A", "A"])["input_count"] == 2
assert build_report(["A", "A"])["valid_count"] == 1

try:
    clean_titles(["A", 100])
except ValueError as exc:
    assert str(exc) == "每个标题必须是字符串"
else:
    raise AssertionError("传入数字时应当拒绝")

print("全部检查通过")
```

运行：

```powershell
.\.venv\Scripts\python.exe check.py
```

输出：

```text
全部检查通过
```

`try`后面的`else`只在没有抛出异常时执行，因此能发现“应该拒绝，却没有拒绝”的错误。这里数字是刻意的错误输入，静态类型工具提示类型不匹配是合理的。

不要用`python -O`运行这些检查，优化模式会关闭`assert`。处理用户输入的校验应像`clean_titles`中那样显式抛异常，不能依赖断言；下一步再学习`unittest`组织更多测试。

接着自己验证文件层失败：临时把输入内容改为`["A", 100]`，运行`app.py`，应输出`ERROR 处理失败：每个标题必须是字符串`且退出码为1。验证后恢复示例输入。不要修改或删除原有学习数据。

## 6. 配置不是写死在代码里的秘密

**环境变量**是运行程序时从系统或终端传入的字符串配置。以后API密钥、模型名和地址会用到它。先用不敏感的演示值理解：

```powershell
$env:APP_LABEL = "study"
.\.venv\Scripts\python.exe -c "import os; print(os.getenv('APP_LABEL', 'local'))"
Remove-Item Env:APP_LABEL
.\.venv\Scripts\python.exe -c "import os; print(os.getenv('APP_LABEL', 'local'))"
```

输出依次为`study`和`local`；`os.getenv`第二个参数是变量不存在时的默认值。字符串`"123"`也不会自动变成整数。

这里只改变当前终端的演示配置。真实API密钥不写进代码、不打印到日志、不加入Git；如果将来用`.env`文件，需要额外的读取方式，Python不会因为文件名叫`.env`就自动读取它。

## 7. 常见错误与排查顺序

| 现象 | 常见原因 | 先检查什么 |
|---|---|---|
| 安装成功却提示找不到库 | 安装和运行使用了不同解释器 | 对比`sys.executable`与`python -m pip --version`的路径 |
| 找不到输入文件 | 路径、文件名或目录层级不一致 | 打印`input_path`；确认是`data/input.json`，不是隐藏了`.txt`后缀 |
| JSON解析失败 | 使用单引号、尾逗号或无效文本 | JSON字符串使用双引号，先对照完整示例 |
| 输出顺序不稳定 | 去重时直接把集合当作结果 | 题目要求保留首次出现顺序，本例按列表顺序收集 |
| 修改后输出还像旧结果 | 程序本次失败，旧报告仍在 | 检查本次日志和退出码，不只打开旧文件 |
| 检查永远显示成功 | 只打印成功，没有比较结果 | 用已知输入断言具体值，并验证应该失败的输入 |
| 导入测试就写了文件 | 文件读写在模块顶层直接执行 | 将运行入口放进`main`和主入口判断 |
