## 175小时内的取舍

- 使用一个主要模型服务、一个接口框架和一种简单检索实现，先理解请求与数据如何流转，再决定是否需要编排框架。
- 首次RAG可以从内存中的小规模向量与元数据开始，理解检索后再根据需求选择持久化；不把多种向量数据库都列为必修。
- Agent只需理解工具调用，最多加入一个可解释、受约束的工具；多Agent、自主浏览、复杂工作流不列必修。
- 本地大模型推理、微调、PyTorch完整课程、分布式训练退出本路线。设备和预算在实际选型前核对，当前不据未确认参数作运行承诺。
- 前端只需要能展示和调用后端的最小界面或接口文档，不另启前端就业路线。

## 路线结束时应具备什么

能够独立运行并修改项目，解释数据导入、切分、检索、模型请求、引用和API返回的完整过程；能处理无检索结果、服务超时、错误输入和模型返回异常；用固定问题集说明效果与不足；能从日志和测试定位至少几种实际遇到的问题。

项目达到约定范围后即可投递匹配岗位，投递不必等Java完成。开始Java后允许少量维护本项目，维护计入75小时技术返修预算，不并行新增另一套大模型课程。通过用户实际完成情况更新状态；不会因为计划到期或累计175小时就自动记为达标。
