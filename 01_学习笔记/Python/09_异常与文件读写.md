## 1. 异常：运行时遇到的失败

有些代码语法正确，但数据不适合当前操作。例如 `int("abc")` 无法把文字转成整数，读取一个不存在的文件也会失败。Python 会抛出**异常**；如果程序没有处理它，当前执行会停止，并打印报错信息。

### 1.1 先读 Traceback 的末尾

下面是一个**故意报错**的独立示例：

```python
def parse(text):
    return int(text)

print(parse("abc"))
```

报错的末尾类似下面这样，文件位置和行号以实际脚本为准：

```text
  File ".../示例.py", line 2, in parse
    return int(text)
ValueError: invalid literal for int() with base 10: 'abc'
```

读报错时按这个顺序找：

1. 最后一行的 `ValueError` 是异常类型：这里是值不适合转换。
2. 后面的文字说明失败原因：`'abc'` 不是合法的整数文本。
3. 向上找最近的 `File ... line ...` 和代码行，定位到 `int(text)`。
4. 再向上看是谁调用了这个函数。本例由 `print(parse("abc"))` 开始调用。

常见异常要区分：

| 异常 | 常见原因 |
|---|---|
| `ValueError` | 类型大致合适，但值不符合要求，例如 `int("bad")` |
| `TypeError` | 类型或操作不合适，例如 `None + 1` |
| `FileNotFoundError` | 要读取的路径不存在，或父目录不存在 |
| `KeyError` | 按键读取字典时，键不存在 |
| `NameError` | 使用了没有定义或导入的名字 |

异常名不是让你背下来后全部捕获，而是帮助你确定应该修代码、检查路径，还是处理坏输入。

### 1.2 try / except：只处理预期的失败

需求：输入能转为整数就返回整数；不能转换就返回 `None`，让调用者决定下一步。

独立运行：

```python
def parse_integer(text: str) -> int | None:
    try:
        return int(text)
    except ValueError:
        return None

for text in ["12", " abc ", "", " 0 "]:
    print(repr(text), parse_integer(text))
```

按输入顺序输出：

```text
'12' 12
' abc ' None
'' None
' 0 ' 0
```

逐行理解：

- `try:` 后面的缩进代码是可能出现预期异常的操作。
- 转换成功，`return int(text)` 直接返回整数，不进入 `except`。
- 出现 `ValueError`，转去匹配的 `except ValueError:`，返回 `None`。
- `repr(text)` 只是为了让空字符串和两端空格在输出中看得见。
- `0` 是合法整数；`None` 表示没有得到整数。失败不能用 `0` 代替，否则会混淆这两种情况。

这个函数约定接收字符串。如果别人传入 `None`，`int(None)` 抛出的是 `TypeError`，本函数不会捕获。捕获范围应和约定一致，不能为了让程序安静就写裸 `except:` 或把所有异常都吞掉。尤其是拼错变量名之类的程序错误，应当修正。

完成后可做 **I01**。

### 1.3 转换成功后，还要检查规则

“能变成整数”不代表“可以当订单数量”。数量还必须大于 `0`。

独立运行：

```python
def positive_quantity(text: str) -> int | None:
    try:
        quantity = int(text)
    except ValueError:
        return None
    if quantity <= 0:
        return None
    return quantity

values = [positive_quantity(text) for text in ["2", "0", "-3", "2.5"]]
print(values)

total = 0
for value in values:
    if value is not None:
        total += value
print(total)
```

按顺序输出：

```text
[2, None, None, None]
2
```

`"0"` 和 `"-3"` 转换成功，但是违反正数规则；`"2.5"` 在整数转换时失败。`None` 不能拿来做加法，调用者先判断它是否有效。

判断“有没有结果”时可以写 `value is not None`。不要把 `if value:` 当成所有场景的有效性判断，因为合法的 `0` 也是假值；在允许 `0` 的问题里，它会被错误排除。

**就地练习：** 定义 `nonnegative_price(text)`，合法整数且大于等于 `0` 时返回它，否则返回 `None`。检查 `"0"`、`"8"`、`"-1"`、`"8.5"`。

```python
def nonnegative_price(text: str) -> int | None:
    try:
        price = int(text)
    except ValueError:
        return None
    if price < 0:
        return None
    return price

print([nonnegative_price(x) for x in ["0", "8", "-1", "8.5"]])
```

输出 `[0, 8, None, None]`。零元单价在这条规则下有效，不应被当作转换失败。

### 1.4 else、finally 与 raise 的基础用法

先知道它们分别做什么，不需要把每次处理异常都写成完整的四段：

- `else`：`try` 正常执行完、没有异常时才执行，用来写成功后的操作。
- `finally`：离开这段异常处理时执行，常用于收尾；正常、异常以及函数返回时都会经过它。
- `raise`：主动抛出异常，让调用者知道这个操作无法按约定完成。

独立运行：

```python
def show_conversion(text: str) -> None:
    try:
        value = int(text)
    except ValueError as error:
        print("转换失败", type(error).__name__)
    else:
        print("转换成功", value)
    finally:
        print("本次检查结束")

show_conversion("2")
show_conversion("bad")
```

按顺序输出：

```text
转换成功 2
本次检查结束
转换失败 ValueError
本次检查结束
```

`as error` 把捕获的异常放进变量 `error`，可以查看类型或错误说明。`else` 内再发生的异常不会由同一组 `except` 处理；因此只把需要处理的操作放进 `try`，不要把整份程序都塞进去。`finally` 不表示失败被修好了，未处理的异常仍会向外传播，也不要在里面随意 `return` 把原来的结果或错误盖掉。

什么时候使用 `raise`？例如一个函数承诺返回有效数量，而不是返回“成功或失败”的结果，可以这样写：

```python
def require_quantity(text: str) -> int:
    value = int(text)
    if value <= 0:
        raise ValueError("数量必须大于 0")
    return value

for text in ["2", "0", "bad"]:
    try:
        print(require_quantity(text))
    except ValueError as error:
        print("无效：", error)
```

按顺序输出：

```text
2
无效： 数量必须大于 0
无效： invalid literal for int() with base 10: 'bad'
```

`raise ValueError("...")` 是你主动指出规则不满足。`return None` 与抛出异常都是可用的接口设计，调用方的处理方式不同。I01、I02 题目要求返回 `None`，不能擅自改成抛异常。

## 3. 文本文件：open、with、模式和编码

### 3.1 看懂打开文件的一行

`open(路径, "r", encoding="utf-8")` 返回一个文件对象。`with ... as file:` 把它交给变量 `file`，缩进块里的代码使用它；离开块时自动关闭文件，即使块内遇到异常，也会完成关闭。

文件的常用模式：

| 模式 | 做什么 | 原文件存在时 | 不存在时 |
|---|---|---|---|
| `"r"` | 读文本 | 读取，不修改 | 抛出 `FileNotFoundError` |
| `"w"` | 写文本 | 打开时清空原内容，再写入 | 创建文件，父目录要存在 |
| `"a"` | 追加文本 | 在原内容末尾写入 | 创建文件，父目录要存在 |

`"r"` 是默认模式，但学习时写出来更清楚。`encoding="utf-8"` 指定文本按什么规则编码或解码，适合本项目提供的 UTF-8 数据。它不是自动猜测文件编码；错误编码可能产生乱码或解码异常。

`"w"` 在打开时就可能清空文件，不是等到第一条 `write()` 才清空。所以写入前要核对输出路径，不能指向“练习数据”。

### 3.2 先读原行，再决定如何清洗

文件的每行通常带有换行符。不同任务有不同的空白规则，不能一律 `strip()`：

```python
line = " Alice \n"

print(repr(line.rstrip("\r\n")))
print(repr(line.strip()))
```

独立运行后依次输出：

```text
' Alice '
'Alice'
```

- `rstrip("\r\n")` 只去掉末尾的回车和换行，保留内容两端的普通空格。
- `strip()` 去掉两端空白，包括空格、制表符和换行。
- 两者都不删除字符串中间的空格。`"Alice Smith".strip()` 仍是 `"Alice Smith"`。

如果是原样保存字段空格，就只处理换行；如果题目明确要求去名字两端空白，才使用 `strip()`。

### 3.3 读取练习名字：保留顺序与重复

I03 的要求是：去两端空白、转小写、跳过空行；没有要求去重。

把下面的完整示例保存为习题目录里的 `示例_读名字.py`，运行：

```python
from pathlib import Path

base = Path(__file__).resolve().parent
input_file = base / "练习数据" / "names.txt"
names = []

with open(input_file, "r", encoding="utf-8") as file:
    for line in file:
        name = line.strip().lower()
        if name:
            names.append(name)

print(names)
print(len(names))
```

按顺序输出：

```text
['alice', 'bob', 'alice']
3
```

解释处理顺序：

1. `for line in file` 逐行读出字符串，包括行末换行。
2. 先 `strip()`，纯空白行变成 `""`；再 `lower()` 统一大小写。
3. `if name:` 只在名字非空时成立；这里用真假判断正好符合需求。
4. `append()` 按读取顺序保存每个名字，没有使用集合，因此第二个 `alice` 还在。
5. 文件关闭后，列表 `names` 仍然可以使用。

如果一次读取整个文件，可用 `file.read()`，结果是一个字符串；`file.readlines()` 得到行字符串列表。逐行处理时直接遍历文件即可，不必先把所有原始行存进内存。

### 3.4 写入与追加：换行要自己安排

把下面的完整示例保存为同目录的新脚本运行。它只在“我的输出”写一个演示文件：

```python
from pathlib import Path

base = Path(__file__).resolve().parent
output_dir = base / "我的输出"
output_dir.mkdir(exist_ok=True)
output_file = output_dir / "文字演示.txt"

with open(output_file, "w", encoding="utf-8") as file:
    file.write("第一行\n")
    file.write("第二行\n")

with open(output_file, "a", encoding="utf-8") as file:
    file.write("第三行\n")

with open(output_file, "r", encoding="utf-8") as file:
    print(file.read(), end="")
```

按文件中的顺序输出：

```text
第一行
第二行
第三行
```

`write()` 不会自动在末尾加换行；`\n` 是换行符。最后的 `end=""` 防止 `print()` 在已有换行后再加一个空行。本例每次运行先用 `w` 重写，再用 `a` 追加一行，因此重复运行仍是三行。如果只用 `a`，重复运行就会不断累积。

**就地练习：** 将 `["alice", "bob", "alice"]` 每个名字一行保存到“我的输出/names_clean.txt”，重跑不增加重复行，再读回检查。不要求改变列表中的重复名字。

## 4. JSON 文件：写入对象，再恢复对象

前一模块用过 `dumps()` 和 `loads()`。它们处理的是字符串；文件版本少了末尾的 `s`：

| 函数 | 输入 | 结果 |
|---|---|---|
| `json.dumps(对象)` | Python 对象 | 返回 JSON 字符串 |
| `json.loads(字符串)` | JSON 字符串 | 返回 Python 对象 |
| `json.dump(对象, 文件)` | Python 对象和打开的文件 | 写入文件 |
| `json.load(文件)` | 打开的文件 | 返回从文件恢复的对象 |

先理解步骤，再运行下面的完整示例：准备字典 → 打开输出文件 → 写入 JSON → 关闭 → 重新打开读取 → 比较内容。

按本页约定保存新脚本运行：

```python
import json
from pathlib import Path

base = Path(__file__).resolve().parent
output_dir = base / "我的输出"
output_dir.mkdir(exist_ok=True)
output_file = output_dir / "record.json"
record = {"姓名": "小林", "分数": [80, 90]}

with open(output_file, "w", encoding="utf-8") as file:
    json.dump(record, file, ensure_ascii=False, indent=2)

with open(output_file, "r", encoding="utf-8") as file:
    restored = json.load(file)

print(restored == record)
print(sum(restored["分数"]))
```

按顺序输出 `True`、`170`。文件中内容为：

```json
{
  "姓名": "小林",
  "分数": [
    80,
    90
  ]
}
```

`ensure_ascii=False` 让中文可直接阅读；`indent=2` 使用两格缩进，便于查看。它们影响文本表示方式，不改变字典原来的数据含义。

本阶段使用字符串键的普通字典，以及列表、字符串、数字、布尔值和 `None`。JSON 中布尔值和空值写成 `true`、`false`、`null`，`load()` 会还原为 Python 的 `True`、`False`、`None`。集合不能直接用默认 JSON 转换；元组会变成 JSON 数组，读回为列表，不保证任意 Python 对象原样往返。

JSON 文件应当包含一份完整的 JSON 数据。不要用 `a` 把多个字典接在一起；这样通常不能再由一次 `load()` 读回。空文件或损坏的 JSON 会抛出 `json.JSONDecodeError`，不能把它默认为“空字典”而不说明。

**就地练习：** 保存 `{"有效数量": 0, "商品": []}` 到“我的输出/empty_summary.json”，再读回检查。这份数据是合法空结果，和没有任何内容的文件不同。

## 5. CSV 读取：表格先变成一行行字典

CSV 是常见的文本表格。练习的 `orders.csv` 有两个字段：

```text
product,quantity
 Pen ,2
book,3
eraser,bad
,4
```

第一行是**表头**，说明两列名字。后面每行是一条记录。CSV 可能用引号保护含逗号的字段，例如商品名 `"pen, blue"`；不能用简单的 `split(",")` 代替可靠的 CSV 解析。

### 5.1 DictReader 怎么工作

按本页约定保存并运行这个完整示例：

```python
import csv
from pathlib import Path

base = Path(__file__).resolve().parent
input_file = base / "练习数据" / "orders.csv"

with open(input_file, "r", encoding="utf-8", newline="") as file:
    reader = csv.DictReader(file)
    print(reader.fieldnames)
    for row in reader:
        print(row)
        print(type(row["quantity"]).__name__)
```

第一行输出 `['product', 'quantity']`。之后按文件顺序，每条记录先打印字典，再打印一行 `str`。第一条字典是：

```text
{'product': ' Pen ', 'quantity': '2'}
```

关键点：

- `csv.DictReader(file)` 用第一行表头作为字典的键。
- `reader.fieldnames` 是表头名字列表。
- 每次循环得到一行字典 `row`。CSV 中的 `2` 读出来是字符串 `"2"`，不会因为长得像数字就自动变成整数。
- `DictReader` 不会替你去字段两端空格，所以 `product` 仍是 `" Pen "`。
- CSV 读写时用 `newline=""`，由 `csv` 模块处理换行，避免 Windows 下常见的多余空行问题。
- 完全空白行会被读取器跳过；`,` 这种有分隔符的空字段行仍是一条记录，应按规则检查。

### 5.2 把坏行分成“字段检查”和“数量检查”

本题的有效记录必须满足：商品去两端空白并转小写，商品非空，数量可转为整数且大于 `0`。

先把一行的处理拆开：

1. 取出原始字符串。
2. 规范商品名，检查是否为空。
3. 把数量字符串转为整数；转换失败是无效行。
4. 转换成功后检查正数规则。
5. 全部满足才生成包含 `product` 和整数 `quantity` 的字典。

除了样例中的坏数字与空商品，还要理解字段缺失：`DictReader` 遇到一行列数不足，会把缺少的字段值设为 `None`；列数多于表头时，默认把多出的部分放在 `None` 这个键下。不能直接对这些 `None` 调用 `strip()`。

下面将以上过程提取为函数。先逐句对照规则，再运行完整示例，不必先记住整段程序：

```python
import csv
from pathlib import Path

def clean_row(row: dict) -> tuple[dict | None, str]:
    if None in row:
        return None, "字段数量超过表头"

    raw_product = row.get("product")
    raw_quantity = row.get("quantity")
    if raw_product is None or raw_quantity is None:
        return None, "缺少字段"

    product = raw_product.strip().lower()
    if not product:
        return None, "商品为空"

    try:
        quantity = int(raw_quantity.strip())
    except ValueError:
        return None, "数量不是整数"
    if quantity <= 0:
        return None, "数量必须大于 0"

    return {"product": product, "quantity": quantity}, ""

base = Path(__file__).resolve().parent
input_file = base / "练习数据" / "orders.csv"
clean = []
invalid_count = 0
reasons = []

with open(input_file, "r", encoding="utf-8", newline="") as file:
    reader = csv.DictReader(file)
    if reader.fieldnames != ["product", "quantity"]:
        raise ValueError("表头应为 product,quantity")

    for row in reader:
        record, reason = clean_row(row)
        if record is None:
            invalid_count += 1
            reasons.append(reason)
            continue
        clean.append(record)

print(clean)
print(sum(record["quantity"] for record in clean))
print(invalid_count)
print(reasons)
```

给定练习文件按顺序输出：

```text
[{'product': 'pen', 'quantity': 2}, {'product': 'book', 'quantity': 3}]
5
2
['数量不是整数', '商品为空']
```

再看循环的职责：

- `record, reason` 接收函数返回的两项：清洗结果和失败原因。
- `record is None` 表示本行无效，计数一次后用 `continue` 跳到下一行。
- 有效记录才放入 `clean`，因此数量求和时都是整数。
- 本例要求表头和这份练习一致，包括列顺序；结构不符合时主动报错，而不是把整个文件误当成零条有效数据。
- 坏行返回 `None`，不让预期的单行数据问题中断整份文件；路径错、表头错等文件问题仍需要指出并修正。

这里没有去重规则，不要自行按商品名或数量去重。后面的项目才会明确提出按订单编号去重。

**就地练习：** 不需要改动原始 CSV。把以下字典逐个交给上面已定义的 `clean_row()`，预测清洗结果，再运行检查。将这些调用接在完整示例末尾：

```python
for row in [
    {"product": " Pen ", "quantity": "0"},
    {"product": "book", "quantity": ""},
    {"product": "eraser", "quantity": None},
    {"product": "pen", "quantity": "2"},
]:
    print(clean_row(row))
```

## 6. CSV 写入：字段、表头和重复运行

写 CSV 也不是直接把字典 `print()` 到文件。用 `DictWriter` 明确列名和列顺序：

- `fieldnames=["product", "quantity"]` 决定第一列与第二列。
- `writeheader()` 写表头；只创建 writer 不会自动写它。
- `writerows(clean)` 写多条记录；`writerow(一条字典)` 写一条。
- 用 `"w"` 重新生成当前结果，用 `newline=""` 交给 CSV 模块处理换行。

下面是独立的完整示例，**不依赖上一节的 clean**。按运行约定保存到习题目录：

```python
import csv
from pathlib import Path

def save_clean(rows: list[dict], path: Path) -> None:
    with open(path, "w", encoding="utf-8", newline="") as file:
        writer = csv.DictWriter(file, fieldnames=["product", "quantity"])
        writer.writeheader()
        writer.writerows(rows)

def read_clean(path: Path) -> list[dict]:
    with open(path, "r", encoding="utf-8", newline="") as file:
        return list(csv.DictReader(file))

base = Path(__file__).resolve().parent
output_dir = base / "我的输出"
output_dir.mkdir(exist_ok=True)

clean = [{"product": "pen", "quantity": 2},
         {"product": "book", "quantity": 3}]
output_file = output_dir / "clean.csv"
save_clean(clean, output_file)
read_back = read_clean(output_file)
print(len(read_back), sum(int(row["quantity"]) for row in read_back))

empty_file = output_dir / "empty_clean.csv"
save_clean([], empty_file)
print(len(read_clean(empty_file)))
```

按顺序输出：

```text
2 5
0
```

`clean.csv` 中内容为：

```text
product,quantity
pen,2
book,3
```

`empty_clean.csv` 中只有一行表头 `product,quantity`，不是完全空文件。即使 `rows` 是空列表，`writeheader()` 仍然执行。`clean.csv` 的读回数量再次是字符串，因此求和仍须 `int()`；CSV 不保留原 Python 对象的类型信息。

**就地练习：** 连续运行这个脚本两次，确认第一条打印两次都是 `2 5`，文件中没有新增两条重复记录。把 `clean` 改成空列表，确认对应文件仍有表头，读回是空列表。

## 7. 文件问题与坏行问题要分别处理

| 情况 | 发生什么 | 合理处理 |
|---|---|---|
| 输入文件不存在 | `open(..., "r")` 抛出 `FileNotFoundError` | 提示并检查路径，不把它当成零条订单 |
| 完全空的 CSV 文件 | `reader.fieldnames` 是 `None` | 按“缺少表头”报告；不能直接下标访问第一条记录 |
| CSV 只有正确表头 | 表头正常，但循环没有数据行 | 合法空输入，清洗列表为空，统计为零 |
| 空字段、坏数字、非正数量 | 某一行不符合数据规则 | 计入无效并记录原因，继续其他行 |
| 列数与表头不一致 | 可能出现 `None` 值或 `None` 键 | 先检查结构，再处理字段 |
| CSV 的引号等格式损坏 | 读取器不一定自动拒绝所有情况；严格解析可能抛出 `csv.Error` | 区分文件格式错误与业务字段错误，报告问题，不凭空补值 |
| JSON 空白或损坏 | `json.load()` 抛出 `json.JSONDecodeError` | 说明文件内容不合法；不能静默当成空字典 |
| 输出目录不存在 | 写文件时可能抛出 `FileNotFoundError` | 先创建你自己的输出目录 |

例如下面的独立脚本用于展示不存在的文件如何提示；确保指定的演示文件未创建，按本页约定保存运行：

```python
from pathlib import Path

base = Path(__file__).resolve().parent
input_file = base / "练习数据" / "不存在的演示文件.txt"

try:
    with open(input_file, "r", encoding="utf-8") as file:
        content = file.read()
except FileNotFoundError:
    print("输入文件不存在，请检查脚本位置与文件名。")
else:
    print(content)
```

文件不存在时输出提示。它没有新建原始数据，也没有用空结果冒充成功。`except FileNotFoundError` 放在文件打开周围；处理单行数字转换的 `except ValueError` 放在转换周围。处理范围越明确，越容易判断真正出了什么问题。

测试空文件、错误表头等边界时，在“我的输出”中新建临时测试数据，并在测试脚本中明确把输入指向这些测试文件；不要清空或改写练习原数据。
