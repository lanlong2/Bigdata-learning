## 1. 类型注解：把函数的使用约定写出来

以前我们可以写 `def area(width, height):`，但调用的人不知道：宽和高应该是数字还是字符串？函数返回数字，还是只负责打印？类型注解能让这些约定直接出现在代码里。

### 1.1 参数与返回值的写法

独立运行下面的代码：

```python
def area(width: int, height: int) -> int:
    return width * height

print(area(3, 4))
```

输出：

```text
12
```

逐部分理解定义这一行：

- `width: int`：约定 `width` 接收整数。冒号后的 `int` 是类型说明。
- `height: int`：约定 `height` 也接收整数。
- `-> int`：约定函数返回整数。
- 最后的 `:`：开始函数体，它仍然是函数定义必须的冒号。

注解不改变 `return` 的作用。返回值由函数体实际执行的代码决定。可以把这项技能用于习题 **M01**。

### 1.2 注解不会自动检查，也不会自动转换

先预测，再独立运行：

```python
def twice(value: int) -> int:
    return value * 2

print(twice(3))
print(twice("3"))
```

按打印顺序输出：

```text
6
33
```

第二次传入的是字符串。字符串乘以 `2` 表示重复两次，所以得到字符串 `"33"`。普通 Python 不会因为写了 `value: int` 就拒绝它，也不会把它变成整数。编辑器或专门的类型检查工具可能给出提醒，这和运行时检查是两件事。

要真正转换，必须调用 `int()`：

```python
def parse_twice(value: int | str) -> int:
    return int(value) * 2

print(parse_twice("3"))
print(parse_twice(3))
```

按顺序输出两行 `6`。`int | str` 表示约定接收整数或字符串；这仍是说明。`int(value)` 才是实际转换。如果传入 `"abc"`，转换会失败，下一模块会教你处理这种失败。当前 **M02** 只要求处理题目给出的合法输入。

### 1.3 变量、容器与 None 的注解

变量也可以写注解：`count: int = 3`。同样，它不会强制检查以后赋给 `count` 的值。

容器注解还可以说明里面装的东西：

| 写法 | 约定 |
|---|---|
| `list[str]` | 列表中的每个元素是字符串 |
| `set[int]` | 集合中的每个元素是整数 |
| `dict[str, int]` | 字典的键是字符串，值是整数 |
| `tuple[str, int]` | 固定两项的元组，第一项字符串，第二项整数 |
| `tuple[int, ...]` | 长度不固定，每项都是整数的元组 |
| `int | None` | 结果可能是整数，也可能是 `None` |

这里的方括号说明类型，不是在创建列表或取下标。`list[str]` 不等于 `[]`，也不等于字符串列表的实际值。

独立运行：

```python
def total_quantities(quantities: list[int]) -> int:
    return sum(quantities)

def find_score(name: str, scores: dict[str, int]) -> int | None:
    return scores.get(name)

def show_total(quantities: list[int]) -> None:
    print(total_quantities(quantities))

print(find_score("alice", {"alice": 90}))
print(find_score("bob", {"alice": 90}))
result = show_total([2, 3])
print(result)
```

按顺序输出：

```text
90
None
5
None
```

`find_score()` 找不到名字时返回 `None`，所以返回注解不能只写 `int`。`show_total()` 只负责打印，没有明确 `return`，实际返回 `None`，可写 `-> None`。打印出来的 `5` 和函数返回的值要分开理解。

**就地练习：** 写 `join_names(names)`，约定输入字符串列表，返回用英文逗号连接的字符串；用 `["alice", "bob"]` 检查。再说明：把数字放进列表，注解会替你转换吗？

<details>
<summary>参考与检查结果</summary>

```python
def join_names(names: list[str]) -> str:
    return ",".join(names)

print(join_names(["alice", "bob"]))
```

输出 `alice,bob`。注解不转换元素；`join()` 遇到整数元素会报错。

## 2. 导入模块：使用已经写好的代码

当一段函数要供多个程序使用时，反复复制容易漏改。可以把函数存进一个文件，让其他程序导入它。

本阶段可以把一个可导入的 `.py` 文件理解为一个**模块**。Python 自带的模块和你自己写的模块，都通过 `import` 使用。

### 2.1 三种常用导入写法

独立运行：

```python
import math
from math import sqrt
import math as m

print(math.sqrt(16))
print(sqrt(16))
print(m.sqrt(16))
```

按顺序输出三行 `4.0`。

| 导入语句 | 后续调用 | 说明 |
|---|---|---|
| `import math` | `math.sqrt(16)` | 导入模块，通过“模块名.成员名”访问 |
| `from math import sqrt` | `sqrt(16)` | 从模块取出指定名字，直接使用 |
| `import math as m` | `m.sqrt(16)` | 为模块取别名，当前文件改用这个名字 |
| `from math import sqrt as root` | `root(16)` | 为导入的成员取别名 |

点号表示访问这个模块提供的名字。别名只影响当前代码怎样称呼它，不会修改模块文件，也不会创建一个新库。

例如，写了 `import math`，后面直接调用 `sqrt(16)` 会出现 `NameError`，因为当前文件没有单独导入 `sqrt` 这个名字。初学时可以优先使用 `import 模块名`，调用来源更容易看清。

### 2.2 标准库和第三方库

`math`、`json`、`csv`、`pathlib` 是 Python **标准库**，随 Python 提供，本节无需安装其他库。第三方库由其他开发者提供，使用前可能需要安装到运行代码的同一个 Python 环境里。本节先把标准库和自己的模块用熟，不需要额外安装。

不要把自己的文件起名为 `json.py`、`csv.py`、`math.py`、`typing.py` 或 `pathlib.py`。当前目录下的同名文件可能遮住真正的标准库，导致“明明导入了，为什么找不到功能”。同一目录下也不要让文件名与要使用的包名重复。

### 2.3 用标准库 JSON 保存一段结构化内容到字符串

字典是 Python 中的对象；JSON 是一种交换数据的文本格式。例如配置、统计结果都可以用 JSON 表达。本节先处理字符串，下一模块再把它写进文件。

独立运行：

```python
import json

data = {"城市": "杭州", "数量": 3}
text = json.dumps(data, ensure_ascii=False)
restored = json.loads(text)

print(text)
print(type(text).__name__)
print(restored == data)
```

按顺序输出：

```text
{"城市": "杭州", "数量": 3}
str
True
```

- `json.dumps(data)`：把字典等对象转换为 JSON **字符串**，返回值放入 `text`。
- `ensure_ascii=False`：中文直接显示；默认写法会用转义形式表示中文，数据本身仍可还原。
- `json.loads(text)`：把 JSON 字符串还原为 Python 对象。
- `restored == data`：比较内容是否相等，不是比较打印的外观。

字典打印时可能用单引号，但 JSON 要求字符串用双引号，不能把 `str(data)` 当成正确的 JSON 序列化方法。

**就地练习：** 把 `{"商品": "pen", "数量": [2, 3]}` 转成保留中文的 JSON 字符串，再还原。打印还原后 `"数量"` 对应的列表总和。

<details>
<summary>参考与检查结果</summary>

```python
import json

record = {"商品": "pen", "数量": [2, 3]}
text = json.dumps(record, ensure_ascii=False)
restored = json.loads(text)
print(sum(restored["数量"]))
```

输出 `5`。

## 3. 导入自己的模块：两个文件真正分开保存

为避免改动已有答卷，在你选定的“我的输出”目录中建立独立的 `模块入门` 文件夹。本小节只在这个示例文件夹里操作。

保存后的结构必须是：

```text
我的输出/
  模块入门/
    helpers.py
    run_examples.py
```

第一步，创建 `helpers.py`，只写下面的代码：

```python
def clean_name(name: str) -> str:
    return name.strip().lower()
```

`strip()` 去掉名字两端空白，`lower()` 转为小写。函数仍然是你之前学过的函数，只是换到了单独的文件里。

第二步，创建同目录的 `run_examples.py`：

```python
import helpers

print(helpers.clean_name(" Alice "))
```

第三步，在编辑器中运行保存好的 `run_examples.py`；也可以在终端先进入 `模块入门` 文件夹，再运行：

```powershell
python run_examples.py
```

如果你的 Windows 环境一直使用 `py` 启动 Python，可以将命令开头换成 `py`。输出：

```text
alice
```

程序运行 `import helpers` 时，找到 `helpers.py`，使其中的函数可通过 `helpers.clean_name` 使用。导入时写模块名 `helpers`，不写 `helpers.py`，也不加引号。

你也可以把 `run_examples.py` **替换**成下面的版本，然后再次运行：

```python
from helpers import clean_name

print(clean_name(" Alice "))
```

输出仍只有一行 `alice`。这是另一种导入写法，当前练习保留一个版本即可。

不要把“`helpers.py`：”这样的文件名提示写进代码；不要把两段代码合成一个文件；编辑器中确认文件后缀确实是 `.py`，而不是 `.py.txt`。完成后可做 **M03**。

## 4. 入口保护：导入时不自动运行演示

假如你把 `print(clean_name(" Alice "))` 直接写在 `helpers.py` 最外层，导入时也会打印。因为**首次导入模块会执行它的顶层代码**；同一进程的普通重复导入通常会使用已经加载的模块。

我们想要：直接运行 `helpers.py` 时可以测试函数；导入它时只提供函数，不自动演示。因此把 `helpers.py` 替换为：

```python
def clean_name(name: str) -> str:
    return name.strip().lower()

if __name__ == "__main__":
    print(clean_name(" Alice "))
```

逐部分理解：

- `__name__` 是 Python 为当前模块设置的名字，前后各有两个下划线。
- 直接运行这个文件时，它的 `__name__` 是字符串 `"__main__"`。
- 从别的文件 `import helpers` 时，它的 `__name__` 是 `"helpers"`。
- `if` 下面缩进的演示只在条件成立时执行。

在 `模块入门` 文件夹分别运行：

```powershell
python helpers.py
```

输出一行 `alice`。

```powershell
python run_examples.py
```

也只输出一行 `alice`，来自 `run_examples.py` 自己的调用。导入过程没有额外打印。

**函数定义要放在入口保护外面。** 如果把函数也缩进到 `if` 中，导入时条件不成立，函数不会被定义，其他文件就无法导入它。以后一个程序有 `main()` 函数时，常在入口保护中写 `main()`，把真正开始读写文件、打印结果等操作放进这个入口。

**就地练习：** 在 `helpers.py` 里再定义 `clean_product()`，功能也是去两端空白、转小写。在入口保护里演示 `" Pen "`。从另一个文件导入并调用 `clean_product(" BOOK ")`，应该打印几行？

<details>
<summary>检查结果</summary>

只打印一行 `book`。`helpers.py` 中的演示没有执行。直接运行 `helpers.py` 时，其入口保护中安排的演示才会执行。

</details>

## 5. 包：用文件夹组织多个模块

一个文件能放一个模块；模块越来越多时，可用**包**把有关的模块放进同一文件夹。先看这个最小结构：

```text
包入门/
  run.py
  tools/
    __init__.py
    cleaning.py
```

如果你想运行这个示例，在“我的输出”中另建 `包入门` 文件夹，按结构创建文件。不要修改前面的双文件示例。

`tools/__init__.py` 先留空，文件必须存在；它让这里的 `tools` 按普通包组织。Python 还支持没有这个文件的另一种包机制，本节不使用那种结构，也不要据此认为所有包都必须有此文件。

在 `tools/cleaning.py` 中写：

```python
def clean_name(name: str) -> str:
    return name.strip().lower()
```

在 `run.py` 中写：

```python
from tools.cleaning import clean_name

print(clean_name(" Alice "))
```

进入 `包入门` 文件夹，运行 `python run.py`，输出 `alice`。`tools.cleaning` 表示包 `tools` 中的模块 `cleaning`；这里用点号，不用文件路径的斜杠。

`__init__.py` 可以为空，也可以安排包初始化代码。导入包时它会被执行，所以不要在这里随意写演示打印或自动改动文件。习题 **M05** 只要求读结构、写出导入语句，不要求再创建一套包。

### 5.1 了解 __all__ 的边界

你可能会见到 `from 某模块 import *`。它会把一批名字带进当前文件，容易让名字来源不清；本教程优先使用明确导入。

`__all__` 是一个名字列表，用来约定 `import *` 导出的名字。例如把包的 `tools/__init__.py` **替换**为：

```python
from .cleaning import clean_name

__all__ = ["clean_name"]
```

这里 `.cleaning` 的前导点表示“当前包里面的 cleaning 模块”。现在包本身也提供 `clean_name`，`run.py` 可替换为：

```python
from tools import clean_name

print(clean_name(" Alice "))
```

输出仍是 `alice`。这是因为 `__init__.py` 中的导入把函数放到了包的名字中，**不是因为写了 `__all__` 就自动创建了函数**。

若写 `from tools import *`，这个例子的 `__all__` 让它导出 `clean_name`。模块也可以定义自己的 `__all__`，影响从该模块进行星号导入的行为。它不做权限保护，不禁止显式导入，也不控制所有导入方式。包里的函数或子模块要怎样提供，仍要由真实的文件和代码决定。

## 6. Path：找数据文件前，先知道路径从哪里开始

模块导入解决“用哪份代码”；文件路径解决“读写哪个数据文件”。二者不要混在一起。

### 6.1 当前工作目录和脚本目录不是同一个概念

- **当前工作目录**：程序启动时用作相对路径起点的文件夹。终端通常可以通过 `cd` 改变它，编辑器也可能设置它。`Path.cwd()` 可以查看它。
- **脚本所在目录**：保存当前 `.py` 文件的文件夹。你从别的目录启动这个脚本，脚本本身仍然在原来的位置。

例如 `Path("names.txt")` 是相对路径，默认从当前工作目录找。它不会自动从脚本目录找。文件明明和脚本放在一起，仍可能因为工作目录不同而找不到。

### 6.2 用脚本位置构建稳定的路径

把下面的完整示例保存为前面 `模块入门` 文件夹里的 `show_path.py`，再运行：

```python
from pathlib import Path

base = Path(__file__).resolve().parent
data_file = base / "练习数据" / "names.txt"

print(base.name)
print(data_file.name)
print(data_file.parent.name)
print(Path.cwd())
```

前三行依次输出：

```text
模块入门
names.txt
练习数据
```

第四行输出你实际的当前工作目录，绝对路径因电脑和启动方式不同而不同。这个例子只构建、打印路径，没有要求 `names.txt` 已经存在，也没有读取或写入它。

按顺序拆开 `base` 这一行：

1. `__file__`：当前脚本的文件位置，由 Python 提供。
2. `Path(__file__)`：把这个位置包装成 `Path` 路径对象。
3. `.resolve()`：得到解析后的绝对路径，消去路径中的 `.`、`..`，并解析可解析的符号链接；构建路径不等于验证目标文件存在。
4. `.parent`：取上一级目录，因此得到脚本所在文件夹。

`base / "练习数据" / "names.txt"` 中的 `/` 是 `Path` 提供的路径拼接操作，不是在做除法。它会按当前系统规则处理路径，Windows 下也可以这样写。`.name` 取路径最后一段的名字。

`__file__` 在保存后运行的 `.py` 文件中可用。在交互终端或部分笔记本环境中可能没有它，因此本项目的文件习题请保存成 `.py` 后运行。

**就地练习：** 在这个脚本中构建与它同目录的 `我的输出/summary.json` 路径，打印最后的文件名与父文件夹名，不实际写文件。

## 7. 常见问题与完成自检

| 现象 | 先检查什么 |
|---|---|
| 注解写了 `int`，结果却是字符串重复 | 注解不会转换；需要实际调用 `int()` |
| `ModuleNotFoundError` | 文件是否保存、名字是否正确、两个示例文件是否同目录、当前运行的是不是正确的入口 |
| `NameError` | 导入的是整个模块还是某个成员？调用时是否用了对应的名字？ |
| 导入时多打印一次 | 被导入文件最外层是否有演示？是否放进入口保护？ |
| 导入不到自己写的函数 | 函数是否错误地放进了入口保护；名字是否拼错？ |
| 标准库出现奇怪的“没有这个属性” | 自己的文件是否和标准库重名？改名后重新启动运行进程 |
| `__file__` 未定义 | 是否在交互终端运行？改为保存 `.py` 后运行 |
