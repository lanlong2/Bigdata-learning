## 每次学习怎么操作

1. 在项目中阅读当天教材和题目。
2. 先用桌面 **MySQL 数据学习** 进入已配置的工作区，再按 **Ctrl+O** 打开项目内对应 `.sql` 文件。若标题显示 `<none>`，点击 SQL 正文后按 **Ctrl+9**（SQL 编辑器 → 上下文 → 设置活动连接），选择已有的 **MySQL 数据学习**；左上角的“新建连接”按钮用于创建其他连接。
3. 新查询连接先执行 `USE sql_learning;`。选中要运行的语句，按 **Ctrl+Enter** 查看结果；整份脚本执行通常为 **Alt+X**，初始化前先读清空范围。
4. 按 **Ctrl+S** 保存代码。执行 SQL 与保存文件是两件事，都需要按实际目的操作。
5. 检查 Git 改动，提交并推送，GitHub 才会更新。

## Git 提交与上传

下面命令写在 VS Code 或 PowerShell 终端中，不写入 DBeaver SQL 编辑器。例子只提交基础查询作答；改了其他文件时明确加入对应路径。

```powershell
Set-Location 'C:\Users\35081\Desktop\bigdata-learning'
git status
git diff -- '02_习题册/SQL/00_基础查询/我的作答.sql'
git add -- '02_习题册/SQL/00_基础查询/我的作答.sql'
git diff --cached
git commit -m 'SQL：更新MySQL基础查询练习'
git push origin main
```

`status` 看哪些文件变化；`diff` 看已跟踪文件的修改；`add` 选择本次要保存的内容；`commit` 在本机建立版本；`push` 上传到 GitHub。全新文件先直接打开检查。只有确认所有改动都需要提交时，才使用 `git add .`。

也可以在 VS Code 的“源代码管理”里暂存指定文件、填写提交说明、提交并推送。**Ctrl+S 本身不会上传到 GitHub。**

本轮教材迁移是否已提交、推送，以 `git status` 和提交记录为准；不能因为本地文件更新，就认为 GitHub 已更新。

## 换电脑继续学习

1. 新电脑第一次克隆仓库；已有仓库时，先处理本地未提交改动，再用 `git pull --ff-only` 获取新版本。
2. 按 [00_环境与关系表](../SQL/00_环境与关系表.md) 安装 MySQL 8.4 LTS 和 DBeaver，建立专用学习库及学习账号。
3. 执行 [00_重建练习库.sql](../SQL/练习数据/00_重建练习库.sql)，再执行 [01_验证学习环境.sql](../SQL/练习数据/01_验证学习环境.sql)。
4. 打开新电脑项目里的作答文件，关联它自己的 MySQL 数据源。

课程初始化会重建四个已命名的课程表（含模块 07 的任务表），请先备份自己的练习数据。不要把它当成同步个人数据库内容的操作。

## 项目文件与数据库数据

`.sql` 保存 SQL 文字；MySQL 的活动数据由数据库服务管理，位于项目外。GitHub 不会替你执行 SQL，也不会自动同步两台电脑的数据库内容。

课程结构和固定样例数据用初始化脚本重建；自己的数据库修改如果需要跨电脑保留，应另做逻辑备份，再恢复到目标电脑。DBeaver 可以通过数据库工具导出备份，或使用 MySQL 的 `mysqldump`。账号密码、客户端状态和活动数据库文件不提交到仓库。
