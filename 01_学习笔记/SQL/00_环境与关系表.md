# 00 环境与关系表

状态：待学习。前置：会打开文件、复制文字；不需要先会 Python 或建表语法。

本模块完成后，你应能解释数据放在哪里，在 Windows 上连接专用学习库，执行课程脚本，运行第一条查询。

## 1. 先把几个名称分清

**数据库**是按规则组织并长期保存数据的地方；**数据库管理系统**是管理这些数据的软件，本教程使用 PostgreSQL。一个 PostgreSQL 服务可以管理多个数据库，建立连接时要指定其中一个。

**表**像有规则的二维表格。**列**说明某类信息，例如客户名、城市；**行**是一条记录，例如一位客户。同一列有规定的数据类型，编号可以用整数，姓名用文本，日期用日期类型。列顺序和查询结果顺序是两回事；数据不会因为先插入就保证先显示。

课程的 `customers`（客户）表如下。本文用 `NULL` 明确标出缺失值，客户端可能显示为空白或 `[null]`。

| customer_id | customer_name | city |
| --- | --- | --- |
| 1 | ada | 北京 |
| 2 | bo | 上海 |
| 3 | cy | 北京 |
| 4 | dan | 广州 |
| 5 | eve | NULL |

`customer_id` 是客户编号；同名客户仍可用不同编号区分。`NULL` 表示这里没有已知值，不等于数字 0，也不等于空字符串 `''`，模块 02 会专门练习。

这里把 `customer_id` 设为**主键**：它唯一标识一行，不能重复，也不能为 `NULL`。两位客户可以同名，但不能共用同一个主键编号。主键怎样写进建表语句、怎样由数据库检查，会在模块07系统学习；现在先理解编号的作用。

**关系数据库**把不同种类的事实放在不同表中，用编号建立联系。`orders.customer_id = 1` 指向客户 `ada`；`orders.product_id = 1` 指向商品 `pen`。先分别查询各表，模块 04 再学习把表连接起来。

课程另外两张表的列如下，先认识列的含义即可：

| 表 | 列 | 含义 |
| --- | --- | --- |
| products（商品） | product_id | 商品编号，整数 |
| products | product_name | 商品名，文本 |
| products | category | 类别，`stationery` 是文具，`home` 是家居 |
| products | unit_price | 单价，保留两位小数的数值 |
| orders（订单） | order_id | 订单编号，整数 |
| orders | customer_id | 客户编号，可缺失 |
| orders | product_id | 商品编号 |
| orders | quantity | 购买数量，正整数 |
| orders | order_date | 订单日期，不含一天中的时分秒 |
| orders | status | 状态，`paid` 是已支付，`cancelled` 是已取消 |

本课程一行订单只包含一种商品。比如订单 1001 的客户编号 1、商品编号 1、数量 2，表示 ada 买了两件 pen；订单表只存编号和数量，商品名称和单价放在商品表中。`quantity` 是件数，`quantity × 单价` 才是这一笔金额，模块 04 才要求自己计算订单金额。

## 2. 服务器与客户端各做什么

**服务器**是持续运行、保存数据并执行 SQL 的程序，安装在本机也叫服务器。**客户端**是你操作它的入口，例如图形界面 pgAdmin、命令行 psql，或者将来的 Python 程序。

操作过程是：在客户端写 SQL → 客户端把 SQL 发给 PostgreSQL 服务 → 服务读取或处理数据库 → 客户端展示结果。关闭 pgAdmin 查询窗口不会删除数据库；服务停止时，客户端连接不上。

SQL 文件只是保存 SQL 文字的文件。双击文件、在编辑器里写好 SQL，都不等于已经在数据库运行；必须连接正确的库，再提交给服务器执行。

## 3. Windows 准备环境

本机已检测到 PostgreSQL 17 工具。已有可用 PostgreSQL 时，先使用已有安装并从连接步骤开始；只有尚未安装时才按下面步骤安装。本节提供操作说明，不会替你实际安装或更改服务。

1. 从 [PostgreSQL 官方 Windows 下载页](https://www.postgresql.org/download/windows/)进入其指向的 EDB 安装程序，选择稳定版本。课程使用 PostgreSQL 语法，不选择测试版。
2. 安装组件保留 PostgreSQL Server、pgAdmin 4 和命令行工具；Stack Builder 的扩展包不是本课程前置。
3. 按安装程序设置数据目录和 `postgres` 用户密码，自己保管密码，不把密码写进学习资料或 SQL 文件。
4. 记下端口；默认通常为 `5432`，已有实例占用时以实际安装值为准。编码使用 UTF-8，其他选项可以采用安装程序默认值。
5. 安装完成后启动 pgAdmin 4。如果要使用 psql，可从开始菜单打开 SQL Shell (psql)，也可使用安装目录中的 `bin\psql.exe`。

这一步中的密码是数据库用户密码；pgAdmin 某些版本另有保存密码所需的主密码提示，两者不要混淆。

## 4. 连接并创建专用学习数据库

推荐先用 pgAdmin，不要求同时掌握两个客户端。

1. 在 pgAdmin 左侧展开本机服务器。若没有已注册服务器，右键 Servers → Register → Server：General 中取一个自己看得懂的名字；Connection 中填写 Host `localhost`、Port `5432`（或实际端口）、Maintenance database `postgres`、Username `postgres`，输入安装时的数据库密码。
2. 连上后展开 Databases，右键 Databases → Create → Database，数据库名填 `sql_learning_db`，保存。这里是给数据库取名，不是在 Windows 中建同名文件夹。
3. 右键新建的 **`sql_learning_db`** → Query Tool，确认窗口所连数据库就是它。以后课程操作都在这个专用库内进行。
4. 输入并执行：

```sql
SELECT current_database() AS database_name;
```

预期只有一行：

| database_name |
| --- |
| sql_learning_db |

`current_database()` 是 PostgreSQL 提供的函数，会返回当前连接的数据库名；`AS database_name` 是给结果列起名，模块 01 再详讲。

也可在连接到 `postgres` 的查询窗口运行下面一条 SQL 来创建数据库，再**重新连接** `sql_learning_db`。此操作与上面的图形创建方式二选一；不要重复创建，也不要在 `BEGIN` 事务块中运行它。

```sql
CREATE DATABASE sql_learning_db;
```

数据库已经存在时出现错误，不代表要删除重建；直接连接已有专用库即可。初始化脚本不替你创建数据库，也不替你切换连接。

## 5. 执行课程数据文件

先读这一条：**[00_重建练习库.sql](练习数据/00_重建练习库.sql)每次运行都会清空并重建 `sql_learning` schema。这个 schema 只放课程对象；不要存个人数据，也不要让其他对象依赖它，因为 `CASCADE` 会一并清理依赖对象。务必在专用学习数据库执行。**

在 pgAdmin 的 `sql_learning_db` 查询窗口里，使用 Open File 打开上述 `.sql` 文件，或完整复制其内容。初始化要执行**整份文件**，不要只选中其中一段。界面按钮可能随版本变化，使用 Execute 执行，通常也可以按 F5。

脚本依次创建课程命名空间、三张表、插入练习数据，最后显示三组检查结果：客户数 `5`、商品数 `4`、订单数 `8`。创建表所用的 `CREATE TABLE` 和添加数据所用的 `INSERT` 现在只需要知道用途，模块 07 再学习如何自己写。

如果执行途中报错，应先看第一条错误。脚本采用事务，一组操作共同成功或撤销；若窗口显示事务已中止，先单独运行 `ROLLBACK;` 结束失败事务，排除错误后再运行整份脚本。事务的完整原理在模块 07。

### schema 与 search_path

`schema`（模式）可以理解为数据库内部给表分类的命名空间。层次是：服务器 → 数据库 → schema → 表；它不是电脑文件夹，也不会嵌套子 schema。

课程表的完整名称是 `sql_learning.customers`。每次新开查询连接先运行：

```sql
SET search_path TO sql_learning;
```

这句让当前连接查找短表名时到 `sql_learning` 中找，因此 `FROM customers` 能找到课程表。它不切换数据库，通常也不会替另一个新连接保存设置。新窗口再运行一次即可。另一种写法是始终使用 `FROM sql_learning.customers`，这样无需依赖短表名搜索设置。

## 6. 第一条查询与表查询

先运行一条不读取任何表的SQL，确认连接能执行语句：

```sql
SELECT 1;
```

结果为一列一行，值是 `1`，列标题可能显示为 `?column?`。这只是最小连接检查，不会创建或修改数据；不要求它替代后面的表查询。

再从课程表读取客户：

```sql
SET search_path TO sql_learning;
SELECT customer_id, customer_name FROM customers;
```

`SELECT` 后写想显示的列，逗号分隔；`FROM` 后写从哪张表读取；分号标记语句结束。查询只读取数据，不会更改客户表。

结果包含下列五行，当前没有指定排序，显示顺序可能不同：

| customer_id | customer_name |
| --- | --- |
| 1 | ada |
| 2 | bo |
| 3 | cy |
| 4 | dan |
| 5 | eve |

你也可以运行不读表的表达式：

```sql
SELECT 2 + 3 AS total;
```

结果是一列 `total`、一行 `5`。不用输入 `>>>`、Python 的 `print()` 或教材中的表格结果；只运行 SQL 代码块。

### 如果使用 psql 执行文件

先通过 SQL Shell 按提示输入服务器 `localhost`、数据库 `sql_learning_db`、实际端口、用户名和密码。进入提示符后，可执行：

```text
\i 'C:/Users/35081/Desktop/bigdata-learning/01_学习笔记/SQL/练习数据/00_重建练习库.sql'
```

`\i` 是 psql 客户端的“执行文件”命令，不是 SQL，不能贴进 pgAdmin 查询窗口。路径用正斜杠并加单引号；仓库以后移动时要改成实际路径。`\q` 可以退出 psql。Windows 中文乱码时检查文件保存为 UTF-8；在 psql 中可先执行 `\encoding UTF8` 设置客户端编码，终端本身也需支持 UTF-8；不要为了显示问题修改原始练习数据。

## 7. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| connection refused / 无法连接 | PostgreSQL 服务是否启动，主机、端口是否正确 |
| password authentication failed | 数据库用户名和安装时的密码是否正确 |
| database does not exist | 是否创建了专用库，连接名是否拼写一致 |
| relation "customers" does not exist | 当前数据库是否正确；是否执行初始化；新窗口是否设置 `search_path` |
| 只显示一条检查结果 | 客户端可能切换不同结果页，或只执行了当前选中语句 |
| 语法错误指向逗号或引号 | 使用半角英文符号，SQL 文字值使用英文单引号 |
