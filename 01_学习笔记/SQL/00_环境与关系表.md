# 00 环境与关系表

状态：待学习。前置：会打开文件、复制文字；不需要先会 Python 或建表语法。

本模块使用 **MySQL 8.4 LTS + DBeaver Community 中文界面**。完成后，你应能解释数据放在哪里，在 Windows 上连接专用学习库，执行课程脚本，运行第一条查询。这里提供可在新电脑复现的操作步骤；材料改版和助手配置不代表你已经学完本模块。

## 1. 先把几个名称分清

**数据库**是按规则组织并长期保存数据的地方；**数据库管理系统**是管理这些数据的软件，本教程使用 MySQL。一个 MySQL 服务可以管理多个数据库，本课程的专用库名是 `sql_learning`。

**表**像有规则的二维表格。**列**说明某类信息，例如客户名、城市；**行**是一条记录，例如一位客户。同一列有规定的数据类型，编号可以用整数，姓名用文本，日期用日期类型。列顺序和查询结果顺序是两回事；数据不会因为先插入就保证先显示。

课程的 `customers`（客户）表如下。本文用 `NULL` 明确标出缺失值，客户端可能显示为空白或 `[null]`。

| customer_id | customer_name | city |
| --- | --- | --- |
| 1 | ada | 北京 |
| 2 | bo | 上海 |
| 3 | cy | 北京 |
| 4 | dan | 广州 |
| 5 | eve | NULL |

`customer_id` 是客户编号；同名客户仍可用不同编号区分。`NULL` 表示这里没有已知值，不等于数字 0，也不等于空字符串 `''`，模块 02 会专门练习。

这里把 `customer_id` 设为**主键**：它唯一标识一行，不能重复，也不能为 `NULL`。两位客户可以同名，但不能共用同一个主键编号。主键怎样写进建表语句、怎样由数据库检查，会在模块 07 系统学习；现在先理解编号的作用。

**关系数据库**把不同种类的事实放在不同表中，用编号建立联系。`orders.customer_id = 1` 指向客户 `ada`；`orders.product_id = 1` 指向商品 `pen`。先分别查询各表，模块 04 再学习把表连接起来。

课程另外两张表的列如下，先认识列的含义即可：

| 表 | 列 | 含义 |
| --- | --- | --- |
| products（商品） | product_id | 商品编号，整数 |
| products | product_name | 商品名，文本 |
| products | category | 类别，`stationery` 是文具，`home` 是家居 |
| products | unit_price | 单价，精确小数 |
| orders（订单） | order_id | 订单编号，整数 |
| orders | customer_id | 客户编号，可缺失 |
| orders | product_id | 商品编号 |
| orders | quantity | 购买数量，正整数 |
| orders | order_date | 订单日期，不含一天中的时分秒 |
| orders | status | 状态，`paid` 是已支付，`cancelled` 是已取消 |

本课程一行订单只包含一种商品。比如订单 1001 的客户编号 1、商品编号 1、数量 2，表示 ada 买了两件 pen；订单表只存编号和数量，商品名称和单价放在商品表中。`quantity` 是件数，`quantity × 单价` 才是这一笔金额，模块 04 才要求自己计算订单金额。

## 2. 服务器、客户端、文件各做什么

**服务器**是持续运行、保存数据并执行 SQL 的程序，安装在本机也叫服务器。**客户端**是你操作它的入口，本教程使用 DBeaver。

操作过程是：在 DBeaver 写 SQL → DBeaver 把 SQL 发给 MySQL 服务 → 服务读取或处理数据库 → DBeaver 展示结果。关闭查询窗口不会删除数据库；服务停止时，DBeaver 连接不上。DBeaver 本身不替你安装 MySQL 服务。

SQL 文件只是保存 SQL 文字的文件。**Ctrl+S 保存文件、执行 SQL、Git 提交、GitHub 推送，是四个不同操作。** 写好或保存 SQL 不等于已经在数据库运行。MySQL 数据也不保存在你的 `.sql` 文件中，而是由服务管理在自己的数据目录里。

本课程的层次是：**MySQL 服务 → 数据库 `sql_learning` → 表**。MySQL 中 `SCHEMA` 是数据库的同义词，本教程统一称“数据库”，不另建库内 schema。

## 3. Windows 准备 MySQL 8.4 LTS

本机当前使用官方 ZIP 版 MySQL 的用户后台实例，并设置登录自启，没有注册 Windows MySQL 服务。实际版本、非秘密路径与启停步骤见 [本机环境说明](本机环境说明.md)；找不到 Windows MySQL 服务不能据此判断本机数据库没有运行。下面的 MSI 安装流程供新电脑使用。

已有可用 MySQL 8.4 时，先复用已有安装，从连接步骤开始。已有其他版本时先核对版本和课程语法，不要直接覆盖、卸载或重置已有服务。以下步骤供尚未安装的新电脑使用：

1. 从 [MySQL Community Server 官方下载页](https://dev.mysql.com/downloads/mysql/)选择 **8.4 LTS** 系列和 Windows 64 位安装包；若下载页默认显示其他系列，先切换版本。选择 MSI 包可减少手工配置。
2. 安装 MySQL Server。MSI 安装结束后按提示启动 **MySQL Configurator**，它负责配置服务；8.4 的步骤以 Configurator 为准，不照搬只适用于旧版 MySQL Installer 的截图。
3. 在配置类型中选择适合个人学习电脑的 Development／开发选项。启用 TCP/IP；端口通常用 **3306**，已有实例占用时保留或选择实际可用端口，并记下来。本机学习不需要开放外网访问。
4. 为管理员 `root` 设置自己的密码，保管在密码管理器等私人位置。密码不写进学习笔记、SQL 文件、Git 仓库或聊天记录；以后 DBeaver 提示输入时自己填写。
5. 将服务器配置为 Windows 服务，记下实际服务名，例如 `MySQL84`；启用随 Windows 启动。按 Configurator 的 Apply／Execute 完成配置并检查结果。
6. 从 Windows“服务”中确认该 MySQL 服务正在运行。服务名、安装位置和端口以实际配置为准，不假定所有电脑都相同。

DBeaver Community 用来连接服务器。尚未安装时从其官方下载渠道安装，首次启动可选择简体中文；已有中文界面无需重复初始化。MySQL Workbench、Shell、Router 都不是本课程开始查询的前置。

## 4. 首次准备专用库与学习账号

日常连接使用 `sql_learner`，管理员账号仅用于首次准备库和账号。**如果这台电脑已准备好 `sql_learning` 与学习账号，直接跳到第 5 节，不重复创建用户或改密码。**

在 DBeaver 点击“新建数据库连接”（通常也可按 `Ctrl+Shift+N`），选择 **MySQL**。先用管理员连接，主机 `127.0.0.1`、端口 `3306`（已有实例以实际值为准），数据库字段暂留空，用户名 `root`，自己输入安装时设置的密码。

首次连接可能需要下载 MySQL Connector/J 驱动。按 DBeaver 的提示下载兼容驱动，再点击“测试连接”。这一步下载的是客户端与 MySQL 通信所需的驱动，不是安装另一套数据库。

连上后打开该连接的 SQL 编辑器，先创建专用库：

```sql
CREATE DATABASE IF NOT EXISTS sql_learning
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_as_cs;
```

`utf8mb4` 用于保存中文等 Unicode 文字；本课程显式使用 `utf8mb4_0900_as_cs` 排序规则，使文字比较区分大小写和重音。已有同名库时 `IF NOT EXISTS` 不会改动其默认排序规则，应先核对现有用途和配置，不直接覆盖已有数据。

新电脑尚无学习账号时，由管理员逐条执行下面的账号语句。**先把示例中的密码文字换成自己的密码；不要把含真实密码的语句保存进项目。** 用户已存在时停止，复用原账号或请管理员核对，不为通过报错而重设密码。

```sql
CREATE USER 'sql_learner'@'localhost'
    IDENTIFIED BY '请替换成你自己的强密码';

GRANT SELECT, INSERT, UPDATE, DELETE,
      CREATE, DROP, ALTER, INDEX, REFERENCES
ON sql_learning.*
TO 'sql_learner'@'localhost';
```

`'sql_learner'@'localhost'` 表示这个 MySQL 用户的本机账号；权限仅限 `sql_learning`。如果你使用的是别人管理的服务器，账号和授权由管理员提供，连接主机和账号范围也按其实际安排。

准备完成后关闭含密码的临时编辑器并放弃保存，日常改用学习账号连接。不要将管理员密码或学习账号密码提交到 GitHub。

## 5. 用 DBeaver 建立日常连接

再次“新建数据库连接”并选择 MySQL：

| 配置项 | 本机学习目标值 | 简单解释 |
| --- | --- | --- |
| 主机 | `127.0.0.1` | 连接当前这台电脑 |
| 端口 | `3306` | 找到 MySQL 服务入口；冲突时用实际端口 |
| 数据库 | `sql_learning` | 本课程专用学习库 |
| 用户名 | `sql_learner` | 日常学习账号 |
| 密码 | 自己设置的密码 | 按提示亲自输入 |
| 连接名称 | 例如“MySQL 学习库” | 方便辨认的显示名称 |

点击“测试连接”，成功后完成连接。客户端保存密码由你自己选择；无论是否保存，都不把密码放入项目文件。不要为了消除连接报错随意降低认证方式或修改服务器全局设置，先看报错和驱动版本。

在左侧数据库导航器选中该连接，打开 SQL 编辑器。确认编辑器上方的数据源是这个 MySQL 连接。`<none>` 表示尚未关联；在编辑器的数据源选择处关联正确连接，也可使用界面显示的选择连接快捷键。

先执行：

```sql
USE sql_learning;

SELECT DATABASE() AS database_name,
       VERSION() AS server_version,
       CURRENT_USER() AS account_name;

SELECT @@autocommit AS autocommit,
       @@sql_mode AS sql_mode;
```

预期数据库名为 `sql_learning`，服务器版本为 `8.4.x`，账号是学习账号。版本尾部和账号显示以实际服务为准。`USE` 为当前连接选择数据库，不是切换 Windows 文件夹；另一个查询窗口可能使用另一个连接，因此**每次新开窗口先运行 `USE sql_learning;`**。

`@@autocommit = 1` 表示服务器会自动提交显式事务之外成功的语句。DBeaver 工具栏也有自动提交／手动提交设置；本阶段查询与初始化采用自动提交。模块 07 要撤销一组修改时，在同一连接中明确开启和结束事务。

检查 `sql_mode` 含 `STRICT_TRANS_TABLES` 或 `STRICT_ALL_TABLES`，并保留 `ONLY_FULL_GROUP_BY`。前者让 InnoDB 写入的超范围等问题按严格规则处理，后者帮助发现分组查询中没有定义清楚的列；本教程按这些模式讲解。不满足时先核对服务器配置，不为让错误 SQL 通过而关闭规则。

还可以检查库的默认文字设置：

```sql
SELECT DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME
FROM information_schema.SCHEMATA
WHERE SCHEMA_NAME = 'sql_learning';
```

预期 `utf8mb4`、`utf8mb4_0900_as_cs`。这条查询只检查配置。库已存在而配置不同时，应先确认是否是本课程库；改变数据库默认设置也不会自动改变已有表和列。

## 6. 执行课程数据文件

先读这一条：**[00_重建练习库.sql](练习数据/00_重建练习库.sql)每次运行都会先删除 `sql_learning.module07_tasks`（若已创建），再删除并重建 `orders`、`products`、`customers` 三张共享课程表，清空上述四张表中已有的数据。** 模块 07 的任务表需学到该章时再创建。 只在自己的课程学习库运行，需保留的作答保存在项目 SQL 文件中。

脚本不会删除整个数据库，也不删除上述四张表之外的表；它会将专用库的默认文字设置调整为 `utf8mb4`／`utf8mb4_0900_as_cs`，再用该规则创建共享课程表。改变库默认设置不等于修改其他已有表。如果你另外新建其他表并用外键依赖课程表，重建可能因依赖而失败；不要为此随手删除自己的表或关闭外键检查。

操作步骤：

1. 在 DBeaver 的文件菜单打开仓库中的上述 `.sql` 文件，或完整复制它到学习连接的新编辑器。打开文件后再次确认数据源是 MySQL 学习连接。
2. 初始化需要执行**整份文件**。使用“SQL 编辑器”菜单中的“执行 SQL 脚本”（快捷键以菜单显示为准）。不要误用只执行光标所在一条的按钮。
3. 脚本选择专用库，按依赖顺序重建三张表并插入样例数据，最后显示三组检查结果：客户数 **5**、商品数 **4**、订单数 **8**。结果可能分在不同结果页。
4. 左侧导航器未立即显示表时，选中学习库刷新。查询数据是否成功应以 SQL 结果为准，不只看树形列表。

MySQL 的 `CREATE TABLE`、`DROP TABLE` 等结构语句会引发隐式提交。**整份重建脚本不能通过一次 `ROLLBACK` 恢复。** 中途报错时先看第一条错误并保留信息；后面的成功不能替代前面的失败。修正连接、权限或依赖问题后，确认接受清空上述四张课程表的范围，再重新执行完整初始化。

## 7. 第一条查询与表查询

先运行一条不读取任何表的 SQL，确认连接能执行语句：

```sql
SELECT 1;
```

结果为一列一行，值为 `1`。这只是最小连接检查，不会创建或修改数据。

再从课程表读取客户：

```sql
USE sql_learning;

SELECT customer_id, customer_name
FROM customers;
```

`SELECT` 后写想显示的列，逗号分隔；`FROM` 后写从哪张表读取；分号标记语句结束。查询只读取数据，不会更改客户表。

结果包含下列五行，目前没有指定排序，显示顺序可能不同：

| customer_id | customer_name |
| --- | --- |
| 1 | ada |
| 2 | bo |
| 3 | cy |
| 4 | dan |
| 5 | eve |

另一种写法是 `FROM sql_learning.customers`，前面的 `sql_learning` 明确指定数据库。入门练习仍先运行 `USE sql_learning;`，后续统一用短表名。

也可以运行不读表的表达式：

```sql
SELECT 2 + 3 AS total;
```

结果是一列 `total`、一行 `5`。不用输入 `>>>`、Python 的 `print()` 或教材中的表格结果；只运行 SQL 代码块。日常选中要执行的当前语句，按 **Ctrl+Enter**；Ctrl+S 则保存文字到 SQL 文件。

## 8. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 无法连接／Connection refused | MySQL 服务是否运行；主机、实际端口是否正确 |
| Access denied for user | 用户名、账号允许的主机、密码和权限；不要把密码发进项目 |
| Unknown database | 是否已创建 `sql_learning`；数据库字段是否拼写一致 |
| No database selected | 在当前编辑器运行 `USE sql_learning;` |
| Table does not exist | 是否连接同一学习库；是否完整执行初始化；表名大小写是否一致 |
| 中文乱码或大小写匹配不同 | 文件编码是否 UTF-8；库与表是否使用课程规定的字符集、排序规则 |
| 只显示一条检查结果 | 是否切换了不同结果页，或只执行了当前选中语句 |
| 驱动／认证报错 | 是否使用兼容的 MySQL Connector/J；按完整报错定位 |
| 约束／权限／依赖报错 | 看第一条错误，核对学习账号权限与关联表，不关闭检查来绕过 |
| 语法错误指向逗号或引号 | 使用半角英文符号，SQL 文字值使用英文单引号 |

报错时保留完整 SQL、第一条错误、当前连接名和预期结果。密码、连接 URL 中的秘密参数等无关内容先隐藏。

## 9. 就地练习与完成检查

依次自己运行，不只阅读示例：

1. 查询当前数据库名称，确认是自己的 `sql_learning`；解释主机、端口、账号分别做什么。
2. 查询 `products` 的 `product_id, product_name`；应有 `pen`、`notebook`、`eraser`、`mug` 四种商品。
3. 新开查询窗口先运行 `USE sql_learning;`，再查询客户；另试完整表名 `sql_learning.customers`。
4. 用自己的话解释“SQL 文件”“客户端”“服务器”“数据库”“表”，说明保存文件为什么不等于执行查询。
5. 说明重跑初始化会清空哪些课程表，以及 `module07_tasks` 存在时会怎样处理，为什么不能用一次回滚恢复整份脚本。

完成检查：能辨认当前数据库与数据源，初始化成功，能独立执行查询，知道重建范围及保存与执行的区别。达到这些条件后进入 [01_基础查询](01_基础查询.md)。当前仍为待学习，实际完成后再记录。
