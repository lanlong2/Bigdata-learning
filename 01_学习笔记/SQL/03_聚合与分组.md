# 03 聚合与分组

状态：待学习。前置：[02_筛选排序与 NULL](02_筛选排序与NULL.md)。配套：[基础题 Q09—Q12](../../02_习题册/SQL/00_基础查询/题目.md)。新窗口先运行 `USE sql_learning;`。

## 1. 从明细行变成统计结果

普通查询一行订单显示一行结果。**聚合函数**把多行数据汇总为一个结果，例如计算一共几行或数量总和。

| 函数 | 含义 | 缺失值处理 |
| --- | --- | --- |
| `COUNT(*)` | 输入的行数 | 所有行都计数 |
| `COUNT(列名)` | 该列有已知值的行数 | 不计 `NULL` |
| `SUM(列名)` | 合计 | 忽略 `NULL` |
| `AVG(列名)` | 平均值 | 只用非 `NULL` 值计算分母 |
| `MIN(列名)` | 最小值 | 忽略 `NULL` |
| `MAX(列名)` | 最大值 | 忽略 `NULL` |

`COUNT(*)` 中的星号是“计所有行”，不是把每列相加。聚合函数名称后的括号不能省略。

```sql
SELECT COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity,
       AVG(quantity) AS avg_quantity,
       MIN(quantity) AS min_quantity,
       MAX(quantity) AS max_quantity
FROM orders
WHERE status = 'paid';
```

| order_count | total_quantity | avg_quantity | min_quantity | max_quantity |
| --- | --- | --- | --- | --- |
| 7 | 14 | 2 | 1 | 4 |

过程：先从订单表找已支付的 7 行；它们的数量是 2、1、3、4、1、1、2；然后得到数量总和 14、均值 14÷7=2、最少 1、最多 4。`AVG` 显示可能有尾随零，例如 `2.0000`，不影响数值含义。

这里汇总的是**商品件数**，并非销售金额。订单表没有单价，金额要在模块 04 连接商品表后用 `quantity * unit_price` 计算。

## 2. COUNT(*) 与 COUNT(列) 的区别

```sql
SELECT COUNT(*) AS all_orders,
       COUNT(customer_id) AS orders_with_customer
FROM orders;
```

| all_orders | orders_with_customer |
| --- | --- |
| 8 | 7 |

订单 1007 虽没有客户编号，但这行订单存在，所以被 `COUNT(*)` 计入；它不被 `COUNT(customer_id)` 计入。不要把 `COUNT(customer_id)` 当成全部订单数。

已有重复客户编号时，`COUNT(customer_id)` 是非空编号出现的次数，不是不同客户的人数。需要后者可写：

```sql
SELECT COUNT(DISTINCT customer_id) AS known_customer_count
FROM orders;
```

结果为 4（编号 1、2、3、4），缺失编号不计。这里 `DISTINCT` 是聚合参数的一部分，先去掉参数的重复值，再计数。

`AVG` 不把未知值当 0。假如一列只有 10、20、`NULL`，平均值为 15，不是 10。`COUNT(*)` 为 3，`COUNT(该列)` 为 2。

## 3. GROUP BY：每组一行

**分组**是把分组列值相同的记录放到一起，在每组内单独做聚合。按商品编号统计已支付订单：

```sql
SELECT product_id,
       COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity
FROM orders
WHERE status = 'paid'
GROUP BY product_id
ORDER BY product_id;
```

| product_id | order_count | total_quantity |
| --- | --- | --- |
| 1 | 3 | 6 |
| 2 | 2 | 2 |
| 3 | 2 | 6 |

步骤是：筛掉取消订单 → 按 `product_id` 分成三组 → 各组计数、求和 → 按商品编号排序。商品 4 没有任何订单，根本没有输入行，因此不会凭空出现一行 0；模块 04 用左连接处理“也要显示无订单商品”。

初学时遵守一个清楚的规则：分组查询的 `SELECT` 中，普通列写进 `GROUP BY`，其他列通过聚合函数得出。本课程保留 MySQL 的 `ONLY_FULL_GROUP_BY` 模式；不要通过关闭模式，让来源不明确的明细列混进分组结果。MySQL 还会识别部分列之间的函数依赖，当前先用上述明确写法。

```sql
-- 错误示例，不要作为答案执行：同一商品可能有多个不同订单编号。
-- SELECT product_id, order_id, SUM(quantity)
-- FROM orders GROUP BY product_id;
```

每组会变成一行，但这一行该显示哪个 `order_id` 没有定义。要订单明细用普通查询，要每组总数就不选明细编号。模块 06 再学习既保留明细又显示组统计的窗口函数。

也可同时按多列分组：`GROUP BY order_date, status` 表示同一天且同一状态的记录为一组。包含 `NULL` 的分组列会把缺失值集中成一组；这与普通比较中 `NULL = NULL` 不是成立条件并不矛盾，分组与比较规则各有用途。

## 4. WHERE 与 HAVING 分别筛什么

`WHERE` 在分组前筛选原始行。`HAVING` 在聚合后筛选整组。比如“只统计已支付订单，并保留售出数量至少 5 的商品”：

```sql
SELECT product_id,
       COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity
FROM orders
WHERE status = 'paid'
GROUP BY product_id
HAVING SUM(quantity) >= 5
ORDER BY product_id;
```

| product_id | order_count | total_quantity |
| --- | --- | --- |
| 1 | 3 | 6 |
| 3 | 2 | 6 |

`WHERE status = 'paid'` 先确定哪些订单进入统计；`HAVING SUM(quantity) >= 5` 再剔除合计数量只有 2 的商品组。不能写 `WHERE SUM(quantity) >= 5`，此时聚合还没有形成。

MySQL 允许这里写 `HAVING total_quantity >= 5`，引用 `SELECT` 中的输出别名；本例写回 `SUM(quantity)`，更直接显示筛选的统计量。`ORDER BY total_quantity DESC` 也能使用别名。`WHERE` 仍不能在本层引用还未生成的输出别名；别名可用的位置不是所有子句都相同。

筛“每笔至少买 2 件”和筛“每种商品合计至少售出 5 件”是两种问题，不能把 `quantity >= 2` 移到 `HAVING` 期待同样效果。

## 5. 没有匹配行时会发生什么

```sql
SELECT COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity,
       AVG(quantity) AS avg_quantity,
       MIN(quantity) AS min_quantity,
       MAX(quantity) AS max_quantity
FROM orders
WHERE order_id < 0;
```

当前数据没有负编号，因此得到**一行统计结果**：

| order_count | total_quantity | avg_quantity | min_quantity | max_quantity |
| --- | --- | --- | --- | --- |
| 0 | NULL | NULL | NULL | NULL |

没有分组的汇总把全部输入当作一个整体，即使输入为空仍能显示“行数 0”。没有数据的 `SUM` 不是 0，而是 `NULL`。所有输入值都是 `NULL` 的列，`SUM`、`AVG`、`MIN`、`MAX` 也返回 `NULL`。

对同一空输入再加分组：

```sql
SELECT product_id, COUNT(*) AS order_count
FROM orders
WHERE order_id < 0
GROUP BY product_id;
```

这次是**零行**，因为没有任何商品组。不要把“结果没有行”和“有一行，其中计数为 0”混为一谈。

## 6. 把语法顺序连起来

```sql
SELECT product_id, SUM(quantity) AS total_quantity
FROM orders
WHERE status = 'paid'
GROUP BY product_id
HAVING SUM(quantity) >= 2
ORDER BY total_quantity DESC, product_id ASC
LIMIT 2;
```

结果为商品 1、3，各 6 件。理解顺序：读表 → `WHERE` 留行 → `GROUP BY` 分组 → 计算聚合 → `HAVING` 留组 → 形成结果列 → `ORDER BY` 排序 → `LIMIT` 限制。数据库可能采用其他物理执行方法；这里描述语义。
