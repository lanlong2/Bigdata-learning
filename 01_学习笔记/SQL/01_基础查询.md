## 1. 一条 SELECT 怎样阅读

```sql
SELECT product_id, product_name, unit_price
FROM products;
```

从 `FROM products` 理解“数据来自商品表”，再看 `SELECT` 后列出的三列“要显示什么”。逗号分隔多列，最后一个列名后不加逗号，结尾加分号。换行只是为了容易阅读，也可写在一行。

| product_id | product_name | unit_price |
| --- | --- | --- |
| 1 | pen | 3.00 |
| 2 | notebook | 5.00 |
| 3 | eraser | 2.00 |
| 4 | mug | 20.00 |

输出每行对应一条商品记录，列顺序按照 `SELECT` 列表排列。只选这三列不会删除表中其他列。

```sql
SELECT * FROM products;
```

`*` 在这里表示所有列：本数据会多显示 `category`。查看陌生表时可以临时使用；正式作答通常按要求列出所需列，避免多输出或表结构变化影响结果。

SQL 关键字 `SELECT`、`FROM` 大小写都可；本教程统一大写关键字、小写表名和列名。MySQL 的数据库名、表名大小写规则会受操作系统和服务器 `lower_case_table_names` 设置影响；不要依赖本机 Windows 上可能不区分大小写的表现。本教程统一使用小写英文名称，并在所有引用处保持一致。

## 2. 给结果列起别名

**别名**是本次输出时用的名字，不会重命名原表字段。使用 `AS`：

```sql
SELECT product_name AS name, unit_price AS price
FROM products;
```

| name | price |
| --- | --- |
| pen | 3.00 |
| notebook | 5.00 |
| eraser | 2.00 |
| mug | 20.00 |

`AS name` 作用在它前面的 `product_name` 上；下一列仍用逗号分隔。后续查询仍需引用原列 `product_name`。

英文单引号表示**文字值**；MySQL 用反引号（字符 U+0060）包住需要引用的**标识符**。默认 SQL 模式下双引号可表示文字，不把双引号当作通用的列名引用方式。例如：

```sql
SELECT 'pen' AS label;
```

结果是一行固定文字 `pen`，没有从商品表读取。`SELECT product_name FROM products;` 才是逐行读取列。为了减少引号问题，先用 `name`、`price` 等简单英文别名；需要带空格或中文的显示标题时，可用反引号，例如下面这条查询；反引号与英文单引号是两个不同字符。

```sql
SELECT product_name AS `商品名称`
FROM products;
```

## 3. 在查询中计算表达式

**表达式**是能够算出一个值的写法，如列名、数字、加减乘除。常用算术符号是 `+`、`-`、`*`、`/`，括号决定先算什么。

```sql
SELECT product_name,
       unit_price,
       unit_price * 2 AS two_unit_cost,
       unit_price + 1 AS price_plus_one
FROM products;
```

| product_name | unit_price | two_unit_cost | price_plus_one |
| --- | --- | --- | --- |
| pen | 3.00 | 6.00 | 4.00 |
| notebook | 5.00 | 10.00 | 6.00 |
| eraser | 2.00 | 4.00 | 3.00 |
| mug | 20.00 | 40.00 | 21.00 |

数据库对每行分别计算，再显示结果；原单价没有被改成两倍。这里算的是“两件该商品的价格”，不是实际订单金额，订单金额要等模块 04 连接商品和订单。

MySQL 的 `/` 是普通除法，即使两边都是整数也会得到小数结果；要截去小数部分，用 `DIV`：

```sql
SELECT 5 / 2 AS decimal_result,
       5 DIV 2 AS integer_result;
```

结果分别为 `2.5` 和 `2`，普通除法可能显示为 `2.5000`。`DIV` 截去小数部分，不能用它计算需要小数的平均值或单价。除数为 0 时，普通 `SELECT` 中通常得到 `NULL` 并伴随警告；写入语句是否报错还受 SQL 模式影响。不要把除零当作返回 0，本模块不要求处理未知除数。

## 4. DISTINCT 去掉重复的结果行

```sql
SELECT category FROM products;
```

得到四行：三次 `stationery`，一次 `home`。如果只想知道“有哪些类别”，写：

```sql
SELECT DISTINCT category
FROM products;
```

结果只有两个不同的类别：

| category |
| --- |
| stationery |
| home |

`DISTINCT` 对**整组输出列**去重。例如：

```sql
SELECT DISTINCT category, unit_price
FROM products;
```

结果仍是四行，因为三个文具商品价格分别是 3.00、5.00、2.00，`(category, unit_price)` 组合都不一样。

去重不修改原表，也不保证排序。选择 `city` 时，城市缺失值也会作为一种结果保留；多个 `NULL` 在去重结果中合并为一个，不意味着可用 `= NULL` 判断缺失值，判断方式在模块 02。

## 5. 常见错误与边界

| 写法 / 想法 | 问题与修正 |
| --- | --- |
| `SELECT product_id product_name FROM products;` | 少逗号，数据库可能把后一名称当别名；两列应以逗号分开 |
| `SELECT product_name, FROM products;` | 最后一列后多了逗号 |
| `SELECT 'product_name' FROM products;` | 每行显示固定文字，不是读同名列 |
| `SELECT name FROM products;` | `name` 是某条查询的别名，原表列仍为 `product_name` |
| “显示是插入顺序，所以顺序固定” | 没有 `ORDER BY` 就没有顺序保证 |
| 用 `DISTINCT product_id, category` 查类别 | 商品编号不同，整行无法合并；只输出需要去重的类别 |

空表在本模块的普通 `SELECT ... FROM ...` 中会返回零行，而不是一行 0。表达式计算中，`NULL` 与普通数值相加仍为 `NULL`；不应当把缺失值直接理解为零。
