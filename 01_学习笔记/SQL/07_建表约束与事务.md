# 07｜建表、约束与事务：安全地维护自己的练习数据

状态：待学习。前置：[06｜窗口函数](06_窗口函数.md)。对应进阶习题 J12。

本章开始创建表、写入和修改数据。请连接个人 MySQL 8.4 练习数据库，仅操作自己创建的 `sql_learning.module07_tasks` 表；共享 `customers`、`products`、`orders` 保持原样。

```sql
USE sql_learning;
```

## 1. 表结构与数据类型

建表前要决定“一行代表什么”。下面一行代表一项学习任务：

| 列 | 类型与含义 |
| --- | --- |
| `task_id` | `INTEGER`，整数任务编号 |
| `customer_id` | `INTEGER`，可空的关联客户编号，仅演示外键 |
| `task_name` | `VARCHAR(100)`，最多 100 个字符的任务名 |
| `estimated_hours` | `DECIMAL(5,2)`，精确小数，总共最多 5 位数字，其中 2 位小数 |
| `status` | `VARCHAR(20)`，任务状态 |
| `due_date` | `DATE`，日期，可以没有截止日期 |

`DECIMAL(5,2)` 可存例如 `12.50`，整数部分最多 3 位，类型范围为 -999.99 到 999.99；这里另外用约束禁止负数，所以小时数范围为 0 到 999.99。金钱、精确小时数可以使用 `DECIMAL`。写入小数位超过两位的值可能经过舍入，并非一定被拒绝。超范围和无效输入的处理受 SQL 模式影响，本教程要求严格模式 `STRICT_TRANS_TABLES` 或 `STRICT_ALL_TABLES`，不依赖非严格模式下的截断和警告。`DATE` 表示年月日，不保存具体时刻。字符串用单引号，例如 `'todo'`、`'2026-10-20'`；日期列会转换合法的日期文字。

## 2. CREATE TABLE 与约束

`CREATE TABLE` 创建表。列之间用逗号分隔。约束是让数据库拒绝不符合要求的数据的规则：

- `PRIMARY KEY`（主键）：唯一标识一行，同时要求不重复、不为空。
- `NOT NULL`：该列必须提供非空值。
- `UNIQUE`：不允许相同的非空值重复；本例与 `NOT NULL` 一起要求任务名必填且唯一。
- `CHECK (条件)`：检查值，例如小时数非负、状态只允许两个文字。
- `FOREIGN KEY (列) REFERENCES 表(列)`（外键）：非空值必须能在被引用表的指定列找到。本教程用表级外键明确声明关系。
- `DEFAULT 值`：插入时省略这列，则使用默认值；它不是校验规则，也不会替换显式传入的 `NULL`。

在个人练习库执行一次：

```sql
CREATE TABLE sql_learning.module07_tasks (
    task_id INTEGER PRIMARY KEY,
    customer_id INTEGER,
    task_name VARCHAR(100) NOT NULL UNIQUE,
    estimated_hours DECIMAL(5,2) NOT NULL CHECK (estimated_hours >= 0),
    status VARCHAR(20) NOT NULL DEFAULT 'todo'
        CHECK (status IN ('todo', 'done')),
    due_date DATE,
    CONSTRAINT fk_module07_customer
        FOREIGN KEY (customer_id)
        REFERENCES sql_learning.customers(customer_id)
) ENGINE=InnoDB
  DEFAULT CHARSET=utf8mb4
  COLLATE=utf8mb4_0900_as_cs;
```

`ENGINE=InnoDB` 指定支持本课程事务和外键的存储引擎。MySQL 的表级 `FOREIGN KEY` 不能省成只在列后附加 `REFERENCES` 的写法；要检查外键是否存在，可查看 `SHOW CREATE TABLE sql_learning.module07_tasks;` 的结果。

预期：创建成功，表是空的。再次原样建表会提示表已存在；这不是需要删除共享数据的理由。要重复本章，可以先把表名一致改成另一个未使用的练习表名，同时把命名外键换成未使用的约束名；也可以复用现有表并检查其中已有数据。以下结果假定从刚创建的空表顺序操作。

`CHECK` 对 `NULL` 的判断可能是未知而非假，所以“必填且非负”需要同时写 `NOT NULL` 和 `CHECK`。外键列允许空值，因为没有给它加 `NOT NULL`；非空的客户编号必须是练习库已经存在的 1—5。

## 3. INSERT：明确列名，再写值

`INSERT INTO` 写入新行。指定列名能说明每个值对应哪列，也不依赖表定义中的列顺序。

```sql
INSERT INTO sql_learning.module07_tasks
    (task_id, customer_id, task_name, estimated_hours, due_date)
VALUES
    (1, 1, '练习连接', 1.50, '2026-10-20'),
    (2, NULL, '练习窗口', 2.00, NULL);

SELECT task_id, task_name, estimated_hours, status, due_date
FROM sql_learning.module07_tasks
ORDER BY task_id;
```

| task_id | task_name | estimated_hours | status | due_date |
| --- | --- | --- | --- | --- |
| 1 | 练习连接 | 1.50 | todo | 2026-10-20 |
| 2 | 练习窗口 | 2.00 | todo | NULL |

`VALUES` 后每对括号是一行，括号之间用逗号分隔。这里没有指定 `status`，于是使用默认值 `todo`。不要把 `NULL` 写成 `'NULL'`，后者是四个字符组成的文字。

以下写法会被拒绝，理解原因即可，不要与可运行的正常示例连成一批执行：重复 `task_id = 1` 会违反主键；已有任务名重复会违反唯一约束；`estimated_hours = -1` 会违反检查约束；`status = 'unknown'` 会违反状态约束；`customer_id = 999` 会违反外键；缺少必填任务名会违反非空约束。

## 4. UPDATE 与 DELETE：先查范围，再操作

`UPDATE ... SET ... WHERE ...` 修改符合条件的行。先用同样条件查询，确认范围：

```sql
SELECT task_id, task_name, status
FROM sql_learning.module07_tasks
WHERE task_id = 2;

UPDATE sql_learning.module07_tasks
SET status = 'done'
WHERE task_id = 2;

SELECT task_id, status
FROM sql_learning.module07_tasks
ORDER BY task_id;
```

结果：`1 | todo`、`2 | done`。`SET` 右边是新值，`WHERE` 决定改哪些行；省略 `WHERE` 会修改整张表。

`DELETE FROM ... WHERE ...` 删除符合条件的行。它删除整行，不是把某列清空。下面将在事务中练习，然后撤销。

## 5. 事务：一组修改一起确认或撤销

事务是一组需要作为整体处理的操作。`START TRANSACTION` 开始事务，`COMMIT` 提交并确认本次修改，`ROLLBACK` 撤销从本次 `START TRANSACTION` 之后尚未提交的修改。

先练习撤销：

```sql
START TRANSACTION;

UPDATE sql_learning.module07_tasks
SET status = 'done'
WHERE task_id = 1;

DELETE FROM sql_learning.module07_tasks
WHERE task_id = 2;

SELECT task_id, status
FROM sql_learning.module07_tasks
ORDER BY task_id;
-- 本事务中暂时只剩：1 | done

ROLLBACK;

SELECT task_id, status
FROM sql_learning.module07_tasks
ORDER BY task_id;
-- 恢复为：1 | todo、2 | done
```

更新和删除都撤销了。`ROLLBACK` 不会撤销开始事务之前已经提交的那次“把任务 2 改成 done”。它也不是能够找回任意历史数据的恢复工具。

再练习提交，在自己的练习表中确认任务 1 的状态修改：

```sql
START TRANSACTION;

UPDATE sql_learning.module07_tasks
SET status = 'done'
WHERE task_id = 1;

SELECT task_id, status
FROM sql_learning.module07_tasks
ORDER BY task_id;
-- 检查为：1 | done、2 | done

COMMIT;
```

提交后再次查询仍是两项 `done`。这里的任务记录是数据库练习示例，不代表你实际完成了相关学习模块。

MySQL 默认 `autocommit=1`，显式事务之外成功的语句会自动提交；DBeaver 的自动提交／手动提交设置也会影响当前连接，应与模块 00 的检查一致。开始本章前确认客户端没有遗留的未结束事务。需要可撤销的一组操作时，明确使用 `START TRANSACTION`，并在同一连接里完成、检查和结束。

MySQL 的 InnoDB 在重复键等许多语句错误后，通常只撤销失败的那条语句，事务中此前成功的修改仍可能等待提交；不能认为一处报错就自动撤销整组修改。InnoDB 遇到死锁会回滚整个事务；锁等待超时的撤销范围也与配置有关。本课程遇到事务错误时先读取错误，再显式 `ROLLBACK` 结束本次事务，检查状态后重试。不要把预期失败的约束测试夹进准备提交的事务，也不要忽略报错直接提交前面的部分结果。

## 6. 结构变更与删除表：本阶段先理解边界

`ALTER TABLE` 用来改变表结构，`DROP TABLE` 用来删除整张表（结构和数据）。MySQL 的常见结构语句（包括本章的 `CREATE TABLE`、`ALTER TABLE`、`DROP TABLE`）会引发隐式提交，不能因为写了 `START TRANSACTION` 就认为可用 `ROLLBACK` 撤销。本章的回滚练习只针对已经存在的 InnoDB 表中的增删改；建表先在事务外完成。本章不要求执行 `ALTER TABLE`、`DROP TABLE`。`DELETE` 删除选中的行、保留结构；`DROP TABLE` 删除整张表，二者不同。要清理练习对象，先核对数据库、完整表名以及是否仍需要数据。

重建共享练习数据脚本会先删除本章的 `module07_tasks`（若已存在），再重建三张共享表，所以重跑初始化也会清空本章任务记录；自己的作答 SQL 应保存为项目文件。其他自建表不在它的主动删除范围内，若存在额外外键依赖，重建可能报错。不要用真实业务表替代练习表，也不要为了使示例能重复运行而删除整个数据库。
