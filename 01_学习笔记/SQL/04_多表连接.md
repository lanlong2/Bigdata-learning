# 04｜多表连接：把分开的信息放到同一张结果表

状态：待学习。前置：完成 00—03，能查询、筛选、排序、分组汇总并识别 `NULL`。本章对应进阶习题 J01—J04。

使用 MySQL 8.4，先在个人练习数据库运行[练习数据脚本](练习数据/00_重建练习库.sql)。本章只查询该脚本创建的 `sql_learning` 数据。先执行：

```sql
USE sql_learning;
```

`USE` 选择当前连接的数据库；这里让 `orders` 等短表名指向 `sql_learning` 中的课程表。它不改变其他连接的当前数据库，请先确认编辑器使用个人学习连接。

## 1. 为什么一条订单没有客户姓名

练习库把信息分到三张表：

| 表 | 一行表示什么 | 用于关联的列 |
| --- | --- | --- |
| `customers` | 一个客户 | `customer_id` |
| `products` | 一种商品 | `product_id` |
| `orders` | 一笔只包含一种商品的订单 | `customer_id`、`product_id` |

客户姓名存在 `customers`，订单保存客户编号。`JOIN`（连接）按你写的条件，把能匹配的行组成一行结果。它不修改原表，也不是把两张表上下拼接。

先查询一笔订单：

```sql
SELECT order_id, customer_id, product_id, quantity
FROM orders
WHERE order_id = 1001;
```

结果是 `1001 | 1 | 1 | 2`。客户编号 1 对应 ada，商品编号 1 对应 pen。下面让数据库完成这两次查找。

## 2. INNER JOIN：只保留匹配成功的行

`INNER JOIN` 是内连接：左右两边都匹配到，才有结果。`ON` 后写匹配条件。`orders AS o` 给表起临时别名 `o`，后面的 `o.customer_id` 表示订单表中的客户编号；别名只对这一条语句有效，不会改表名。

```sql
SELECT o.order_id, c.customer_name, o.quantity
FROM orders AS o
INNER JOIN customers AS c
    ON o.customer_id = c.customer_id
WHERE o.status = 'paid'
ORDER BY o.order_id;
```

预期结果：

| order_id | customer_name | quantity |
| --- | --- | --- |
| 1001 | ada | 2 |
| 1002 | ada | 1 |
| 1003 | bo | 3 |
| 1005 | bo | 4 |
| 1006 | dan | 1 |
| 1008 | ada | 2 |

理解顺序：从订单找客户编号相等的行 → 保留已支付订单 → 取所需列 → 排序。实际执行方案由数据库选择，这里是理解结果的顺序。

已支付订单原有 7 笔，但这里只有 6 行：1007 的 `customer_id` 是 `NULL`，没有匹配客户。`NULL = NULL` 也不为真，不能用它完成普通等值连接。

`JOIN` 不自动去重。当前客户编号唯一，因此每笔订单最多匹配一个客户；若错误地按非唯一的城市关联，一笔订单可能匹配多个客户，金额就会重复计算。先说明“一行结果代表什么”，再汇总。

## 3. LEFT JOIN：保留左边所有行

`LEFT JOIN` 是左连接：保留左表全部行；右表没有匹配行时，右表的各列以 `NULL` 补齐。

```sql
SELECT o.order_id, c.customer_name, o.quantity
FROM orders AS o
LEFT JOIN customers AS c
    ON o.customer_id = c.customer_id
WHERE o.status = 'paid'
ORDER BY o.order_id;
```

这次有 7 行，1007 对应 `1007 | NULL | 1`，其余行与上一节相同。这里的 `NULL` 是结果中的空值，工具可能显示为空白。

如果报告希望显示“匿名客户”，可用 `COALESCE`。这是一个函数：从左到右返回第一个不是 `NULL` 的值。

```sql
SELECT o.order_id,
       COALESCE(c.customer_name, '匿名客户') AS customer_name
FROM orders AS o
LEFT JOIN customers AS c
    ON o.customer_id = c.customer_id
WHERE o.order_id = 1007;
```

结果：`1007 | 匿名客户`。`COALESCE` 只改变查询结果的显示，不会把表里的 `NULL` 改成文本。传入值要能转换成兼容的类型，例如金额缺失时用数字 `0`，姓名缺失时用文字。

## 4. 连三张表，计算每笔订单金额

订单金额 = 数量 × 商品单价。练习中的每一笔订单只有一种商品，也没有折扣、退款或运费。

```sql
SELECT o.order_id,
       COALESCE(c.customer_name, '匿名客户') AS customer_name,
       p.product_name,
       o.quantity,
       o.quantity * p.unit_price AS amount
FROM orders AS o
LEFT JOIN customers AS c
    ON o.customer_id = c.customer_id
INNER JOIN products AS p
    ON o.product_id = p.product_id
WHERE o.status = 'paid'
ORDER BY o.order_id;
```

预期结果：

| order_id | customer_name | product_name | quantity | amount |
| --- | --- | --- | --- | --- |
| 1001 | ada | pen | 2 | 6.00 |
| 1002 | ada | notebook | 1 | 5.00 |
| 1003 | bo | pen | 3 | 9.00 |
| 1005 | bo | eraser | 4 | 8.00 |
| 1006 | dan | notebook | 1 | 5.00 |
| 1007 | 匿名客户 | pen | 1 | 3.00 |
| 1008 | ada | eraser | 2 | 4.00 |

先连客户并保留匿名订单，再按商品编号找单价，最后筛选支付状态和计算金额。商品编号存在且有效，因此本例商品内连接不会丢订单。只算已支付订单共 7 笔、14 件、40.00 元；不能把已取消的 1004 加进去。

## 5. 保留没有订单的客户：条件应该放哪里

目标是“列出全部客户及其已支付订单数，包括零订单客户”。先把客户放在左边，支付条件写在 `ON` 中：

```sql
SELECT c.customer_id, c.customer_name,
       COUNT(o.order_id) AS paid_order_count
FROM customers AS c
LEFT JOIN orders AS o
    ON c.customer_id = o.customer_id
   AND o.status = 'paid'
GROUP BY c.customer_id, c.customer_name
ORDER BY c.customer_id;
```

| customer_id | customer_name | paid_order_count |
| --- | --- | --- |
| 1 | ada | 3 |
| 2 | bo | 2 |
| 3 | cy | 0 |
| 4 | dan | 1 |
| 5 | eve | 0 |

`ON` 决定哪些右表行有资格匹配。cy 只有取消订单，eve 没有订单，两人都保留。`COUNT(o.order_id)` 不计 `NULL`，因此得到 0；`COUNT(*)` 会数左连接生成的占位行，错误地得到 1。

如果把条件写为 `WHERE o.status = 'paid'`，右表缺失的客户会被筛掉。`NULL = 'paid'` 不为真，cy 和 eve 就消失了。一般规则是：保留左表全部对象、只限制右表的匹配范围时，把右表限制写在 `ON`。

找“没有已支付订单的客户”可以利用必填且唯一的订单编号：

```sql
SELECT c.customer_id, c.customer_name
FROM customers AS c
LEFT JOIN orders AS o
    ON c.customer_id = o.customer_id
   AND o.status = 'paid'
WHERE o.order_id IS NULL
ORDER BY c.customer_id;
```

结果：`3 | cy`、`5 | eve`。不要用可空的其他右表列判断是否匹配，已匹配行也可能在那些列上为空。

## 常见错误和边界

- 两张表都有 `customer_id` 时，使用 `o.customer_id`、`c.customer_id` 明确来源，否则可能出现“列引用不明确”。
- 漏写或写错 `ON` 条件可能让行数成倍增加；先检查订单编号有没有重复，再求和。
- `LEFT JOIN` 保留的是你写在左边的表。以客户为左表的报告不包含匿名订单，因为匿名订单不属于客户表中的任何客户。
- `SUM` 没有可计算值时返回 `NULL`。要把零订单客户金额显示为 0，可以写 `COALESCE(SUM(o.quantity * p.unit_price), 0)`；不要以为 `SUM` 自动返回 0。
- `ORDER BY` 才能保证输出顺序；表的存储顺序和连接顺序都不能代替它。
