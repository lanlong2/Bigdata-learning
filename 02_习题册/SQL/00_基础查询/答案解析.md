## Q01 指定列

```sql
SELECT customer_id, customer_name
FROM customers;
```

结果包含 1/ada、2/bo、3/cy、4/dan、5/eve 五行，顺序不限。列名不加单引号；单引号会使输出变成固定文字。

## Q02 列别名

```sql
SELECT product_name AS item_name, unit_price AS price
FROM products;
```

| item_name | price |
| --- | --- |
| pen | 3.00 |
| notebook | 5.00 |
| eraser | 2.00 |
| mug | 20.00 |

顺序不限。`AS` 仅给本次结果列起名字，不修改原表列名。

## Q03 表达式

```sql
SELECT product_name, unit_price * 4 AS four_unit_cost
FROM products;
```

| product_name | four_unit_cost |
| --- | --- |
| pen | 12.00 |
| notebook | 20.00 |
| eraser | 8.00 |
| mug | 80.00 |

顺序不限。每行使用该商品的单价乘 4，不是把四种商品价格合计。

## Q04 去重

```sql
SELECT DISTINCT category
FROM products;
```

得到 `stationery`、`home` 两行，顺序不限。如果同时选商品编号，每个 `(product_id, category)` 都不同，`DISTINCT` 对整行去重后仍然有四行。

## Q05 支付状态与数量区间

```sql
SELECT order_id, quantity
FROM orders
WHERE status = 'paid'
  AND quantity BETWEEN 2 AND 3
ORDER BY order_id;
```

| order_id | quantity |
| --- | --- |
| 1001 | 2 |
| 1003 | 3 |
| 1008 | 2 |

也可用 `quantity >= 2 AND quantity <= 3`。1004 已取消；1005 虽已支付但数量为 4，均不符合条件。

## Q06 候选集合与括号

```sql
SELECT order_id, product_id
FROM orders
WHERE status = 'paid'
  AND product_id IN (1, 3)
ORDER BY order_id;
```

等价的 `OR` 版本：

```sql
SELECT order_id, product_id
FROM orders
WHERE status = 'paid'
  AND (product_id = 1 OR product_id = 3)
ORDER BY order_id;
```

两版均返回：

| order_id | product_id |
| --- | --- |
| 1001 | 1 |
| 1003 | 1 |
| 1005 | 3 |
| 1007 | 1 |
| 1008 | 3 |

括号把两种商品选择圈成一个整体，再与“已支付”同时成立。当前数据中商品 3 恰好没有取消记录，漏括号可能碰巧得到同样结果；逻辑仍应按需求写对，不能凭当前数据掩盖问题。

## Q07 日期与前两笔

```sql
SELECT order_id, order_date
FROM orders
WHERE status = 'paid'
  AND order_date BETWEEN DATE '2026-10-02' AND DATE '2026-10-04'
ORDER BY order_date DESC, order_id ASC
LIMIT 2;
```

| order_id | order_date |
| --- | --- |
| 1007 | 2026-10-04 |
| 1008 | 2026-10-04 |

先过滤，再按日期从新到旧，同日按唯一订单编号升序；这使前两笔有确定含义。

## Q08 缺失值与文字匹配

第一问：

```sql
SELECT customer_id, customer_name, city
FROM customers
WHERE city <> '北京' OR city IS NULL
ORDER BY customer_id;
```

| customer_id | customer_name | city |
| --- | --- | --- |
| 2 | bo | 上海 |
| 4 | dan | 广州 |
| 5 | eve | NULL |

`NULL <> '北京'` 的结果未知，`WHERE` 只留下条件为真的行，所以缺失城市需要用 `IS NULL` 明确纳入。

第二问：

```sql
SELECT product_id, product_name
FROM products
WHERE product_name LIKE '%e%'
ORDER BY product_id;
```

| product_id | product_name |
| --- | --- |
| 1 | pen |
| 2 | notebook |
| 3 | eraser |

两侧 `%` 表示 `e` 可以位于名字的任意位置；仅写 `'e'` 只匹配整个名字正好为 `e` 的文本。

## Q09 已支付订单总览

```sql
SELECT COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity,
       AVG(quantity) AS avg_quantity,
       MIN(quantity) AS min_quantity,
       MAX(quantity) AS max_quantity
FROM orders
WHERE status = 'paid';
```

| order_count | total_quantity | avg_quantity | min_quantity | max_quantity |
| --- | --- | --- | --- | --- |
| 7 | 14 | 2 | 1 | 4 |

平均数量可能显示多位尾随零。数量总和为 14 件；此题没有计算价格，不能把 14 写成销售额。

## Q10 行存在不代表字段已知

```sql
SELECT COUNT(*) AS all_orders,
       COUNT(customer_id) AS orders_with_customer
FROM orders;
```

结果一行 `8, 7`。订单 1007 的客户编号为 `NULL`；`COUNT(*)` 计入该行，`COUNT(customer_id)` 跳过该字段缺失的行。

## Q11 每种商品的已支付统计

```sql
SELECT product_id,
       COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity
FROM orders
WHERE status = 'paid'
GROUP BY product_id
ORDER BY product_id;
```

| product_id | order_count | total_quantity |
| --- | --- | --- |
| 1 | 3 | 6 |
| 2 | 2 | 2 |
| 3 | 2 | 6 |

商品 4 不在订单表中出现，因此没有可形成分组的输入行；仅按订单分组不会自动补出所有商品。

## Q12 筛组与空输入

第一问：

```sql
SELECT product_id,
       COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity
FROM orders
WHERE status = 'paid'
GROUP BY product_id
HAVING SUM(quantity) >= 5
ORDER BY product_id;
```

| product_id | order_count | total_quantity |
| --- | --- | --- |
| 1 | 3 | 6 |
| 3 | 2 | 6 |

已支付是原始订单条件，放在 `WHERE`；组内数量合计至少 5 是汇总条件，放在 `HAVING`。不能把 `SUM(quantity) >= 5` 放在 `WHERE`。MySQL 允许在 `HAVING` 中引用这里的输出别名，因此 `HAVING total_quantity >= 5` 也是正确的等价写法；参考答案重复聚合表达式便于看清条件作用于汇总结果。

第二问：

```sql
SELECT COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity
FROM orders
WHERE order_id < 0;
```

得到**一行**，`order_count = 0`，`total_quantity = NULL`。零行的和不会自动变为 0。

再观察分组版本：

```sql
SELECT product_id,
       COUNT(*) AS order_count,
       SUM(quantity) AS total_quantity
FROM orders
WHERE order_id < 0
GROUP BY product_id;
```

返回**零行**。没有输入就没有任何 `product_id` 分组；无分组的整体聚合则仍然返回整体统计行。
