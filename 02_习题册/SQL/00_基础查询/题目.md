# SQL 基础查询 Q01—Q12

状态：待练习。使用 PostgreSQL 和统一课程数据；新连接先执行 `SET search_path TO sql_learning;`。仅做已完成前置教材的题目。

表字段速看：

- `customers(customer_id, customer_name, city)`：客户编号、姓名、城市。
- `products(product_id, product_name, category, unit_price)`：商品编号、名称、类别、单价。
- `orders(order_id, customer_id, product_id, quantity, order_date, status)`：订单编号、客户编号、商品编号、数量、日期、状态。

用 SQL 写出答案；除题目指定外不要增加无关输出列。Q01—Q04 没有排序前置，结果行的顺序不限。Q05 起按题目要求排序。

## 阶段一：学完 01 基础查询后

### Q01 指定列

从 `customers` 查询所有客户的 `customer_id, customer_name`。输出五行，不要求筛选或排序。

检查重点：表名、列名、逗号和分号；不要用固定文字替代列。

### Q02 列别名

从 `products` 查询商品名和单价，输出标题分别为 `item_name, price`。不改变原表字段名。

检查重点：别名的位置；结果应有四个商品。

### Q03 表达式

查询所有商品的 `product_name` 和“四件该商品的价格”，第二列标题为 `four_unit_cost`。

检查重点：逐行计算，四个金额为 12.00、20.00、8.00、80.00；不修改原单价。

### Q04 去重

只查询商品表中不同的 `category`，每种类别只出现一次。用一句话说明：如果同时选择商品编号，为何不能只留下两个类别行？

检查重点：`DISTINCT` 的作用范围；不要提前使用分组。

## 阶段二：学完 02 筛选排序与 NULL 后

### Q05 支付状态与数量区间

查询已支付且数量在 2 到 3 之间（包含两端）的订单，输出 `order_id, quantity`，按订单编号升序。

检查重点：组合条件、闭区间；取消订单不进入结果。

### Q06 候选集合与括号

查询已支付且商品编号为 1 或 3 的订单，输出 `order_id, product_id`，按订单编号升序。

分别写两版：第一版使用 `IN`，第二版使用带括号的 `OR`。说明括号圈定了哪一组条件。

### Q07 日期与前两笔

查询 2026-10-02 到 2026-10-04（包含两端）的已支付订单，按日期降序、同日订单编号升序，取前两笔。输出 `order_id, order_date`。

检查重点：使用 `DATE` 值，排序能够打破并列，再限制行数。

### Q08 缺失值与文字匹配

独立写两个查询：

1. 找城市不是北京的客户，**明确包括城市缺失者**，输出 `customer_id, customer_name, city`，按客户编号升序。
2. 找商品名中任意位置包含小写 `e` 的商品，输出 `product_id, product_name`，按商品编号升序。

另写一句话：`city <> '北京'` 为什么不能单独把 `eve` 留下来？

## 阶段三：学完 03 聚合与分组后

### Q09 已支付订单总览

用一条查询输出已支付订单的笔数、数量合计、平均数量、最少数量、最多数量。别名依次为 `order_count, total_quantity, avg_quantity, min_quantity, max_quantity`。

检查重点：过滤发生在统计前；件数不是金额。

### Q10 行存在不代表字段已知

对**全部订单**用一条查询输出总行数 `all_orders` 与客户编号已知的订单行数 `orders_with_customer`。写一句话说明两者为何相差 1。

### Q11 每种商品的已支付统计

只使用 `orders`，按商品编号统计已支付订单笔数和数量合计。输出 `product_id, order_count, total_quantity`，按商品编号升序。

写一句话说明为何商品编号 4 没有出现。暂不要求把无订单商品显示为 0；这是模块 04 的连接问题。

### Q12 筛组与空输入

独立写两个查询并解释差别：

1. 在 Q11 基础上，只留下已支付数量合计至少 5 的商品，按商品编号升序。
2. 在 `orders` 中筛选 `order_id < 0`，不分组，输出 `COUNT(*) AS order_count, SUM(quantity) AS total_quantity`。说明会返回几行、每列是什么值；再说明加上 `GROUP BY product_id`（并选择该分组列）为何行数不同。

检查重点：`WHERE` 留下哪些明细，`HAVING` 留下哪些组；零行和一行 0 / NULL 的区别。
