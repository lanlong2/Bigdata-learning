## J01｜内连接

```sql
SELECT o.order_id, c.customer_name, o.quantity
FROM orders AS o
INNER JOIN customers AS c ON o.customer_id = c.customer_id
WHERE o.status = 'paid'
ORDER BY o.order_id;
```

结果：`1001 | ada | 2`、`1002 | ada | 1`、`1003 | bo | 3`、`1005 | bo | 4`、`1006 | dan | 1`、`1008 | ada | 2`。

订单先按客户编号匹配，再筛选已支付。1007 的客户编号为空，内连接不保留没有匹配客户的订单。

给分：连接条件与内连接 4 分；支付筛选 2 分；输出列与排序 2 分；正确解释匿名订单 2 分。

## J02｜保留零订单客户

```sql
SELECT c.customer_id, c.customer_name,
       COUNT(o.order_id) AS paid_order_count
FROM customers AS c
LEFT JOIN orders AS o
    ON c.customer_id = o.customer_id
   AND o.status = 'paid'
GROUP BY c.customer_id, c.customer_name
ORDER BY c.customer_id;
```

结果：`1 | ada | 3`、`2 | bo | 2`、`3 | cy | 0`、`4 | dan | 1`、`5 | eve | 0`。

客户在左表，支付条件放在 `ON`，这样没有支付订单仍保留。`COUNT(o.order_id)` 跳过空值；`COUNT(*)` 会把没有匹配订单的占位行也算进去。

给分：左表选择与连接 3 分；支付限制位置正确 2 分；计数与分组 3 分；排序及解释 2 分。

## J03｜完整支付明细

```sql
SELECT o.order_id,
       COALESCE(c.customer_name, '匿名客户') AS customer_name,
       p.product_name,
       o.quantity,
       o.quantity * p.unit_price AS amount
FROM orders AS o
LEFT JOIN customers AS c ON o.customer_id = c.customer_id
INNER JOIN products AS p ON o.product_id = p.product_id
WHERE o.status = 'paid'
ORDER BY o.order_id;
```

| order_id | customer_name | product_name | quantity | amount |

## J04｜没有已支付订单

```sql
SELECT c.customer_id, c.customer_name
FROM customers AS c
LEFT JOIN orders AS o
    ON c.customer_id = o.customer_id
   AND o.status = 'paid'
WHERE o.order_id IS NULL
ORDER BY c.customer_id;
```

结果：`3 | cy`、`5 | eve`。cy 虽然有取消订单，但没有符合连接条件的支付订单。

订单编号是非空主键，因此右表编号为空能表明“没有匹配行”。不能随意换成右表某个允许空值的字段，否则可能把已匹配但字段为空的订单当成没有订单。

给分：左连接与支付条件 4 分；正确的空值检测 3 分；结果列和排序 1 分；解释检测字段 2 分。

## J05｜与单笔平均比较

```sql
SELECT o.order_id, o.quantity * p.unit_price AS amount
FROM orders AS o
INNER JOIN products AS p ON o.product_id = p.product_id
WHERE o.status = 'paid'
  AND o.quantity * p.unit_price > (
      SELECT AVG(o2.quantity * p2.unit_price)
      FROM orders AS o2
      INNER JOIN products AS p2 ON o2.product_id = p2.product_id
      WHERE o2.status = 'paid'
  )
ORDER BY o.order_id;
```

结果：`1001 | 6.00`、`1003 | 9.00`、`1005 | 8.00`。内层金额平均为 40/7，外层检查每笔支付订单是否严格大于它。

内外层都限制支付范围，匿名订单无需客户连接，因此参与平均。`AVG` 不带分组保证子查询只有一行。

给分：单值子查询及平均范围 4 分；外层支付范围 2 分；金额与严格大于 2 分；结果列和排序 2 分。

## J06｜多值子查询

```sql
SELECT customer_id, customer_name
FROM customers
WHERE customer_id IN (
    SELECT customer_id
    FROM orders
    WHERE status = 'paid'
)
ORDER BY customer_id;
```

结果：`1 | ada`、`2 | bo`、`4 | dan`。外层对每个客户判断“编号是否在这组值中”；内层重复的编号只是重复候选值，不复制外层行。

给分：`IN` 与单列子查询 4 分；支付条件 2 分；结果列和排序 2 分；解释无重复客户 2 分。

## J07｜分层汇总

```sql
WITH paid_detail AS (
    SELECT o.customer_id, o.quantity * p.unit_price AS amount
    FROM orders AS o
    INNER JOIN products AS p ON o.product_id = p.product_id
    WHERE o.status = 'paid'
)
SELECT c.customer_id, c.customer_name,
       SUM(d.amount) AS total_amount
FROM paid_detail AS d
INNER JOIN customers AS c ON d.customer_id = c.customer_id
GROUP BY c.customer_id, c.customer_name
HAVING SUM(d.amount) >= 10
ORDER BY total_amount DESC, c.customer_id;
```

结果：`2 | bo | 17.00`、`1 | ada | 15.00`。CTE 负责订单金额；主查询按客户汇总、筛选总额。客户内连接自然排除匿名订单。

给分：CTE 及支付金额 3 分；已登记客户范围和分组 3 分；汇总条件 2 分；输出和两级排序 2 分。

## J08｜客户总额与客户均值

```sql
WITH paid_detail AS (
    SELECT o.customer_id, o.quantity * p.unit_price AS amount
    FROM orders AS o
    INNER JOIN products AS p ON o.product_id = p.product_id
    WHERE o.status = 'paid'
      AND o.customer_id IS NOT NULL
),
customer_totals AS (
    SELECT customer_id, SUM(amount) AS total_amount
    FROM paid_detail
    GROUP BY customer_id
)
SELECT c.customer_name, t.total_amount
FROM customer_totals AS t
INNER JOIN customers AS c ON t.customer_id = c.customer_id
WHERE t.total_amount > (
    SELECT AVG(total_amount)
    FROM customer_totals
)
ORDER BY t.total_amount DESC, t.customer_id;
```

结果：`bo | 17.00`、`ada | 15.00`。客户总额为 15、17、5，平均 37/3。分母 3 是有支付订单的已登记客户数；5 是全部已登记客户数，7 是支付订单数，都不是本题要求。

给分：CTE 正确生成客户总额 4 分；正确平均与严格比较 3 分；输出排序 1 分；解释统计单位和分母 2 分。

## J09｜分区序号后筛选

```sql
WITH ranked_orders AS (
    SELECT customer_id, order_id, order_date,
           ROW_NUMBER() OVER (
               PARTITION BY customer_id
               ORDER BY order_date DESC, order_id DESC
           ) AS rn
    FROM orders
    WHERE status = 'paid'
      AND customer_id IS NOT NULL
)
SELECT customer_id, order_id, order_date
FROM ranked_orders
WHERE rn = 1
ORDER BY customer_id;
```

结果：`1 | 1008 | 2026-10-04`、`2 | 1005 | 2026-10-03`、`4 | 1006 | 2026-10-03`。分区后各客户重新从 1 开始；日期相同用编号降序稳定选择。窗口计算晚于同层 `WHERE`，因此外层才能筛选序号。

给分：支付与已登记范围 2 分；分区及两级排序 4 分；外层筛选和输出 2 分；解释层级 2 分。

## J10｜汇总后排名

```sql
WITH customer_totals AS (
    SELECT c.customer_id, c.customer_name,
           SUM(o.quantity * p.unit_price) AS total_amount
    FROM customers AS c
    INNER JOIN orders AS o ON c.customer_id = o.customer_id
    INNER JOIN products AS p ON o.product_id = p.product_id
    WHERE o.status = 'paid'
    GROUP BY c.customer_id, c.customer_name
)
SELECT customer_id, customer_name, total_amount,
       DENSE_RANK() OVER (ORDER BY total_amount DESC) AS rank_no
FROM customer_totals
ORDER BY rank_no, customer_id;
```

结果：`2 | bo | 17.00 | 1`、`1 | ada | 15.00 | 2`、`4 | dan | 5.00 | 3`。按客户总额排名；唯一客户编号只用于最终显示排序，不参与并列判断。

给分：客户支付金额汇总 4 分；正确 `DENSE_RANK` 与排名标准 4 分；输出和排序 2 分。

## J11｜逐笔累计

```sql
WITH paid_detail AS (
    SELECT o.order_id, o.order_date,
           o.quantity * p.unit_price AS amount
    FROM orders AS o
    INNER JOIN products AS p ON o.product_id = p.product_id
    WHERE o.status = 'paid'
)
SELECT order_id, order_date, amount,
       SUM(amount) OVER (
           ORDER BY order_date, order_id
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_amount
FROM paid_detail
ORDER BY order_date, order_id;
```

结果的订单编号依次为 1001、1002、1003、1005、1006、1007、1008；金额依次 6、5、9、8、5、3、4；累计依次 6、11、20、28、33、36、40。

先保留所有支付明细，包括匿名订单，再从第一行累加到当前行。排序列和显式行框架共同定义“逐笔”。

给分：金额与完整支付范围 3 分；窗口两级排序 2 分；显式框架和累计 3 分；输出列与最终排序 2 分。

## J12｜写入与回滚

仅连接个人 MySQL 学习数据库 `sql_learning`，以下从尚未存在本题表的首次执行开始。先确认当前没有未结束事务；建表成功后，再开始下方事务。MySQL 的 `CREATE TABLE` 会隐式提交，不能靠后面的 `ROLLBACK` 撤销建表；本题明确使用支持事务的 InnoDB 表，只观察插入数据的回滚。

```sql
CREATE TABLE sql_learning.j12_notes (
    note_id INTEGER PRIMARY KEY,
    note_text VARCHAR(100) NOT NULL,
    hours NUMERIC(5,2) NOT NULL CHECK (hours >= 0)
) ENGINE = InnoDB;

START TRANSACTION;

INSERT INTO sql_learning.j12_notes (note_id, note_text, hours)
VALUES
    (1, '连接练习', 1.00),
    (2, '窗口练习', 1.50);

SELECT COUNT(*) AS note_count
FROM sql_learning.j12_notes;
-- 2

ROLLBACK;

SELECT COUNT(*) AS note_count
FROM sql_learning.j12_notes;
-- 0
```

建表不在这次数据事务里，因此撤销的是本事务插入的两行，表本身还存在。不要在 `START TRANSACTION` 和 `ROLLBACK` 之间穿插建表、删表或改表，否则这些 DDL 的隐式提交会破坏本题的回滚过程。重复编号违反主键；空文本值 `NULL` 违反非空；负小时数违反检查约束。空字符串并不违反本题的非空约束。

再次作答时，已存在且为空的 InnoDB 本题表可直接执行从 `START TRANSACTION` 开始的事务部分。此示例没有记录实际学习用时。

给分：字段类型和约束 4 分；明确事务及合法两行写入 2 分；回滚和 2→0 验证 2 分；约束及建表保留解释 2 分。
